# 背景音乐分离并发调度

背景音乐分离任务最多同时运行 5 个。每个任务使用独立工作进程和暂停／取消控制；单个任务中的多个输入文件仍按顺序处理。

调度器约每 2 秒重新检查排队任务，结合可用 CPU 核心、当前 CPU 利用率和可用内存决定是否启动下一个任务。Windows NVIDIA GPU 使用 `nvidia-smi` 的当前利用率和剩余显存；macOS Apple GPU 使用 IORegistry 的可选利用率计数及系统可用统一内存。指标缺失、驱动不支持或设备映射不明确时，GPU 任务保持单任务执行。Windows 自动模式选择 CPU 运行环境时，按 CPU 资源调度。

- 并发上限固定为 5；CPU 工作进程限制为 1～4 个计算线程，GPU 工作进程最多 2 个 CPU 线程。GPU 退回 CPU 时仍保留线程限制。
- 新增并发需要给系统预留 CPU 和至少 2 GiB 内存。标准模型／精细模型分别保守预留 6／10 GiB 系统内存；Apple GPU 使用共享内存，预留 10／14 GiB；CUDA 分别预留 4／6 GiB 显存并留出 1 GiB 余量。
- 上述值是调度估算，不是模型峰值内存保证。为保护低内存设备，额外任务按当前空闲内存再次扣除活动任务的预留量。首个任务保留原有执行及加速失败后的 CPU 回退流程，不因显存估算超过设备容量而永久排队。
- CPU／GPU 繁忙或内存不足时，后续任务等待；已运行任务不中断、不重启。运行中暂停的任务仍占用并发名额，因为暂停不会释放模型内存。
- 合并视频、提取字幕保留独占执行。队列按先后顺序处理，不跳过排在前面的独占任务，避免源文件与结果的读写冲突。
- 完成、失败、取消、删除会释放对应名额。退出应用会停止并等待所有活动任务，尚未开始的任务保留在队列中。
- 共用模型和运行环境按任务计数保护，直到最后一个任务结束才标记为空闲。

线程限制通过 PyTorch／BLAS 环境变量传给既有工作程序，兼容 Windows v3 运行环境和现有 macOS 运行环境，无需重新下载模型或重新打包 AI 运行环境。

实现依据：[sysinfo CPU 采样间隔](https://docs.rs/sysinfo/latest/sysinfo/constant.MINIMUM_CPU_UPDATE_INTERVAL.html)、[NVIDIA GPU 查询](https://nvidia.custhelp.com/app/answers/detail/a_id/3751/kw/support%20site)。Apple 驱动计数属于可选探测，键缺失按未知处理。
