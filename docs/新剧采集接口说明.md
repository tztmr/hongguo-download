# 新剧采集接口说明：新剧信息、全集目录、视频下载

核对日期：2026-09-14。范围：当前源码中的新剧采集链路，以及搜索、榜单、指标查询、书城推荐和换一批接口。

第 1–15 节根据路由、请求参数校验、返回值构造和解析代码整理，并使用当前 FastAPI OpenAPI 核对请求参数；其中 JSON 示例为结构示意。新增第 16–18 节合并用户提供的《番茄小说推荐接口整理.md》，并使用项目现有签名执行真实推荐请求、换一批和一个剧目的目录/播放模型查询。**明确标注“实测”的结果来自本次网络请求；其他示例仍不代表实际可用 ID 或地址。本次没有下载视频文件。**

新增内容入口：[推荐接口与字段](#16-番茄小说书城推荐与换一批上游接口)、[现有项目封装](#17-现有项目推荐接口可直接调用)、[可用性实测](#18-推荐接口可用性实测2026-09-14)。

## 1. 先分清两种 API 地址

| 层级 | 谁调用 | 地址形式 | 说明 |
|---|---|---|---|
| 项目对外 API | 你的采集程序调用 | `http://127.0.0.1:8000/api/duanju/...` | 本文主体，项目处理上游请求、设备选择、签名和响应整理 |
| 平台上游 API | 项目后端调用 | `https://...fqnovel.com/...`、`https://reading.snssdk.com/...` | 不是本项目提供的服务地址；具体对应关系见第 13 节 |

本文统一用以下地址举例；部署到其他机器时，替换主机名与端口：

```bash
API_BASE='http://127.0.0.1:8000'
```

在项目根目录启动本地 API（需先安装 `requirements.txt` 中的依赖）：

```bash
python3 -m uvicorn main:app --host 127.0.0.1 --port 8000
```

| 地址 | 作用 |
|---|---|
| `GET /health` | 检查进程和设备池概况，不代表所有上游接口正常 |
| `/docs` | FastAPI 交互式请求文档 |
| `/openapi.json` | 请求参数与路由定义；多数响应使用动态 JSON，完整字段需结合本文和源码 |

桌面程序管理的 sidecar 地址、端口以实际运行配置为准，不要假定一定是 `8000`。这些 HTTP 接口提供数据与单集文件；桌面端自动追剧的启动、暂停、合并和上传调度属于另外的 Tauri 后台功能。

## 2. 接口总览与 ID 对应关系

本文所有项目接口均为 **GET**，参数放在 URL query 中，不需要 JSON 请求体。

| 功能 | 项目接口 | 主要输入 | 成功结果 |
|---|---|---|---|
| 新剧列表 | `/api/duanju/new-releases` | `type`、`days`、`cursor`、`limit` | 剧目数组与分页状态 |
| 榜单发现 | `/api/duanju/rank` | `board`、`type`、`cursor`、`limit` | 榜单剧目与分页状态 |
| 关键词搜索 | `/api/duanju/search` | `key`、`content_type`、`offset`、`passback` | 搜索剧目与分页状态 |
| 推荐首屏 | `/api/duanju/discovery` | `content_type`、`filter_ids`、`selected_items` | 真人剧/漫剧推荐及换页状态，见第 17 节 |
| 推荐换页 | `/api/duanju/discovery/more` | `cell_id`、`offset`、`session_id`、`plan_id` 等 | 下一批推荐及新状态，见第 17 节 |
| 剧目详情 | `/api/duanju/detail` | `book_id` | 上游原始详情 JSON |
| 全集目录 | `/api/duanju/catalog` | `book_id` | 当前上游目录，含每集 `item_id` |
| 剧目指标 | `/api/duanju/series-metrics` | `series_id`、`content_type` | 上线时间与统计指标 |
| 单集播放源 | `/api/duanju/content` | `item_id` | 各清晰度的视频源信息 |
| 单集下载 | `/api/duanju/download` | `item_id`、`definition` | **MP4 二进制，不是 JSON** |
| 密钥查询（可选） | `/api/duanju/key` | `item_id`、`definition` | 已有接口的密钥信息；普通下载流程无需单独调用 |

ID 关系：

```text
新剧 / 榜单的 items[].series_id
    = 同一项的 book_id
    → detail、catalog 的 book_id
    → series-metrics 的 series_id

搜索的 items[].book_id
    → detail、catalog 的 book_id

catalog 的 items[].item_id
    → content、download、key 的 item_id
```

所有 ID 按字符串保存。不要把 19 位 ID 转成 JavaScript `Number`；也不要把剧目 ID 传给单集接口。`first_vid` 只代表一个首集入口，不能代替完整目录。

## 3. JSON 响应与错误处理

本文 `/api/duanju/*` JSON 接口成功时：

```json
{
  "code": 0,
  "msg": "ok",
  "data": {}
}
```

| 字段 | 类型 | 含义 |
|---|---|---|
| `code` | integer | `0` 表示项目封装层成功，非零表示业务错误 |
| `msg` | string | 成功或错误说明 |
| `data` | object / null | 成功数据；项目业务错误时通常为 `null` |

项目主动返回的错误示例：

```json
{
  "code": -2,
  "msg": "分页游标已失效",
  "data": null
}
```

| HTTP 状态 | `code` | 常见场景 | 处理方式 |
|---|---|---|---|
| 400 | `-1` | 不支持的榜单等业务参数 | 修正参数 |
| 400 | `-2` | 新剧或榜单游标失效 | 从第一页重新扫描，依靠已保存 ID 去重 |
| 502 | `-3` | 上游请求、搜索分类、播放模型等失败 | 记录错误，退避后重试，不能当成空列表 |
| 502 | `-4` | 推荐首屏/换页未解析出内容 | 保留错误，不当作已采完；核对频道和返回结构 |
| 502 | `-5` | `/key` 选源或密钥处理失败 | 检查单集信息并重试 |
| 502 | `-8` | 下载准备、播放源或 CDN 下载失败 | 保留任务状态，重试失败单集 |
| 502 | `-9` | 视频解密失败 | 标记失败并保留诊断信息 |
| 502 | `-10` | 开启兼容播放后，转换失败 | 检查兼容转换和 FFmpeg |
| 422 | 无统一 `code` | 缺少必填参数、类型错误、越界或枚举不符 | 读取 FastAPI 的 `detail` 数组并修正请求 |

参数校验错误可能为以下结构，不要假定所有错误都有 `code/msg/data`：

```json
{
  "detail": [
    {
      "type": "missing",
      "loc": ["query", "book_id"],
      "msg": "Field required",
      "input": null
    }
  ]
}
```

`/health` 和 `/` 也不使用上述业务响应包裹。`/download` 成功返回视频、失败可能返回 JSON；保存文件前同时检查 HTTP 状态和 `Content-Type`。

## 4. 新剧列表

### 请求

```http
GET /api/duanju/new-releases?type=playlet&limit=20
```

| 参数 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| `type` | string | 否 | `playlet` | `playlet` 真人剧；`comic_series_rank` 漫剧；`ai_playlet` AI 剧 |
| `limit` | integer | 否 | `20` | 每页条数，范围 `1–20`，实际可能少于请求值 |
| `cursor` | string | 否 | `""` | 第一页省略；下一页原样传上页 `next_cursor` |
| `days` | integer | 否 | 不传 | 范围 `1–30`，含今天的北京时间自然日，不是滚动的 N×24 小时 |

不同类型的时间范围和来源：

| 条件 | 来源 | 实际语义 |
|---|---|---|
| `type=playlet`，不传 `days` | 上游日程/预约列表 `subscribe` | 北京时间当天上新的候选剧目 |
| `type=playlet&days=7` | 逐日查询日程列表 | 今天及之前 6 个自然日 |
| 漫剧 / AI 剧，不传 `days` | 新剧榜 `rank` | 榜单最新收录，**不代表今天上线，也不是全站全集合** |
| 漫剧 / AI 剧，传 `days` | 新剧榜 `rank` | 仅对榜单返回项按上线时间过滤；缺少时间的项会被过滤，不会逐日补全历史榜单 |

```bash
# 今天真人新剧
curl --fail-with-body --get "$API_BASE/api/duanju/new-releases" \
  --data-urlencode 'type=playlet' \
  --data-urlencode 'limit=20'

# 最近 7 天真人新剧
curl --fail-with-body --get "$API_BASE/api/duanju/new-releases" \
  --data-urlencode 'type=playlet' \
  --data-urlencode 'days=7' \
  --data-urlencode 'limit=20'
```

| `data` 字段 | 类型 | 说明 |
|---|---|---|
| `items` | array | 本页剧目，字段见下一节 |

| `source` | string | 真人剧 `subscribe`；漫剧/AI 剧 `rank` |
| `date_scope` | string | `today`、`latest` 或传了 `days` 后的 `recent` |
| `days` | integer / null | 请求中的天数；未传时为 `null` |

### 剧目对象字段（新剧与榜单）

字段类型按当前标准化代码说明；部分文本和元数据直接沿用上游值，客户端仍应容错。

| 字段 | 通常类型 | 含义与缺省行为 |
|---|---|---|
| `series_id` | string | 剧目唯一 ID，采集去重主键 |
| `book_id` | string | 与本条 `series_id` 相同，用于详情和目录请求 |
| `title` | string | 剧名，缺失时空字符串 |
| `cover` | string | 封面地址，缺失时空字符串 |
| `first_vid` | string | 首集视频 ID；可能为空，应以目录为准 |
| `episode_count` | integer | 上游提供的集数，缺失时 `0`；不是完结标记 |
| `content_type` | integer | 上游内容类型，常见 `1` 真人、`1004` 漫剧类；缺失时当前代码回落 `1`，不能单独据此断言类型 |
| `video_category_type` | string | 上游视频分类标识，AI 剧可能有 `ai_video` |
| `release_type` | string | 项目分类：`playlet` / `comic_series_rank` / `ai_playlet`；未识别的综合榜条目可能为空字符串 |
| `duration` | integer | 沿用上游 `duration` 并转整数，缺失 `0`；桌面按秒展示，但这里不验证它是否为整部总时长 |
| `abstract` | string | 剧情简介 |
| `score` | string / number | 上游评分展示值，缺失通常为空字符串；不是热度 |
| `category` | string | 用 ` · ` 拼接的类别标签 |
| `category_tags` | string[] | 类别标签数组 |
| `sub_title` | string | 上游副标题，可能含“全80集”“连载中”等状态文字 |
| `sub_title_list` | object[] | 完结/连载等文字证据，每项为 `{ "content": "全80集" }`，缺失时 `[]`；不是字符串数组或布尔值 |
| `author` | string | 当前取自上游版权/出品字段，不保证是个人作者 |
| `rank_tags` | array | 榜单标签数组；当前新剧/榜单标准化通常为 `[]`，其他发现来源可能包含 `label`、`schema` |
| `online_time` | integer / null | 上线 Unix 秒时间戳，可能缺失；不是固定格式的日期字符串 |
| `play_count` | integer / null | 播放量 |
| `hot_count` | integer / null | 热度值，不能当成播放量 |
| `collect_count` | integer / null | 收藏/追剧指标 |
| `like_count` | integer / null | 点赞指标；当前新剧/榜单标准化通常为 `null` |
| `comment_count` | integer / null | 评论指标；无法确认完整统计时为 `null` |

`null` 表示未知，不等于 `0`。不要用 `episode_count > 0` 判断完结；当前接口没有统一保证的 `is_finished` 字段。

### 分页规则

```bash
NEXT_CURSOR='替换为上一页的data.next_cursor'
curl --fail-with-body --get "$API_BASE/api/duanju/new-releases" \
  --data-urlencode 'type=playlet' \
  --data-urlencode 'days=7' \
  --data-urlencode 'limit=20' \
  --data-urlencode "cursor=$NEXT_CURSOR"
```

1. 后续页保持同样的 `type`、`days`，URL 编码后原样传回游标。
2. 不按返回数量判断结束，也不把 20 条当作总量上限；查看 `has_more`。
3. 当前游标保存在单个服务进程内存，TTL 为 600 秒，且受容量淘汰影响；重启、跨北京时间日期、参数范围变化也可能令游标失效。
4. 不同接口的游标不能混用。多进程部署不能假定任意进程都认识另一进程产生的游标。
5. 持久保存已发现的 `series_id`；游标失效后重新扫描并去重，不把游标当作长期断点。

## 5. 新剧榜 / 其他榜单

```http
GET /api/duanju/rank?board=ranklist_new_rank_sc&type=playlet&limit=20
```

| 参数 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| `board` | string | 否 | `ranklist_hot_sc` | 下表中的榜单标识 |
| `type` | string | 否 | `all` | `all` / `playlet` / `comic_series_rank` / `ai_playlet` |
| `limit` | integer | 否 | `20` | `1–20` |
| `cursor` | string | 否 | `""` | 上一页 `next_cursor`，同一 `board` 和 `type` 下使用 |

| `board` | 名称 |
|---|---|
| `ranklist_hot_sc` | 推荐榜 |
| `ranklist_hot_play_sc` | 热播榜 |
| `ranklist_prestige` | 臻果榜 |
| `ranklist_subscribe` | 预约榜 |
| `ranklist_new_rank_sc` | 新剧榜 |
| `ranklist_hot_search_sc` | 热搜榜 |
| `ranklist_must_watch` | 必看榜 |
| `ranklist_followed` | 收藏榜 |

```bash
curl --fail-with-body --get "$API_BASE/api/duanju/rank" \
  --data-urlencode 'board=ranklist_new_rank_sc' \
  --data-urlencode 'type=comic_series_rank' \
  --data-urlencode 'limit=20'
```

成功 `data` 字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `items` | array | 第 4 节的剧目对象 |
| `next_cursor`、`has_more` | string、boolean | 分页状态，规则同第 4 节 |
| `board`、`board_name` | string | 当前榜单标识和名称 |
| `release_type` | string | 本次请求的类型，含 `all` |
| `source_note` | string | 来源限制说明；空字符串表示没有附加说明 |
| `boards` | array | 可选榜单，每项 `{ "id": "ranklist_hot_sc", "name": "推荐榜" }` |

部分类型没有独立榜单时，后端会从综合榜中过滤该类型，`source_note` 会说明限制。榜单全部翻完不代表平台全部剧目采完。当前桌面自动追剧中，`today` 范围使用新剧接口，其他范围使用新剧榜发现候选。

## 6. 关键词搜索

```http
GET /api/duanju/search?key=示例关键词&content_type=drama&offset=0
```

| 参数 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| `key` | string | 是 | 无 | 非空关键词，需 URL 编码 |
| `content_type` | string | 否 | `drama` | `drama` 真人短剧；`manju` 漫剧，不使用新剧接口的类型字符串 |
| `offset` | integer | 否 | `0` | 非负；后续页使用 `next_offset` |
| `passback` | string | 否 | `""` | 后续页使用 `next_passback`；`offset=0` 时后端强制清空 |

```bash
curl --fail-with-body --get "$API_BASE/api/duanju/search" \
  --data-urlencode 'key=系统' \
  --data-urlencode 'content_type=drama' \
  --data-urlencode 'offset=0'
```

| `data` 字段 | 类型 | 说明 |
|---|---|---|
| `items` | array | 搜索剧目，字段见下表 |
| `has_more` | boolean | 是否继续搜索分页 |
| `next_offset` | integer | 下一页偏移，不要自行加固定页大小 |
| `next_passback` | string | 下一页搜索状态，与偏移一起传回 |
| `raw` | object | 上游原始搜索响应，用于诊断，结构可能变化 |

搜索 `items[]` 字段与第 4 节不完全相同：

| 字段 | 通常类型 | 说明 |
|---|---|---|
| `book_id` | string | 剧目 ID；搜索当前不额外输出 `series_id` |
| `first_vid` | string | 首集入口 |
| `title`、`cover`、`abstract`、`author` | string | 剧名、封面、简介、版权/出品信息 |
| `episode_count`、`content_type` | number / string | 上游集数和类型值，当前搜索解析不强制转整数 |
| `score` | string / number | 评分展示值 |
| `rec_text` | string | 推荐说明 |
| `category` | string | 当前取上游 `sub_title`，不等于标准化后的类别标签数组 |

缺少请求的搜索分类会作为失败返回，不应把这种失败当作“没有搜索结果”。

## 7. 剧目详情

```http
GET /api/duanju/detail?book_id=9000000000000000001
```

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `book_id` | string | 是 | 非空剧目 ID，来自新剧/榜单 `series_id` 或搜索 `book_id` |

```bash
SERIES_ID='替换为实际剧目ID'
curl --fail-with-body --get "$API_BASE/api/duanju/detail" \
  --data-urlencode "book_id=$SERIES_ID"
```

**返回规则是 `{ code: 0, msg: "ok", data: 上游原始响应 }`。** 后端没有将详情整理成统一的 `title`、`episode_count`、`is_finished` 对象，也没有固定、完整的响应模型。上游若自己还有 `data` 层，该层会继续保留，所以不能假定剧名总在 `data.title`。

稳定的剧名、封面和集数优先使用第 4 节列表字段；目录使用第 8 节；指标使用第 9 节。详情用于补充来源信息、识别上游明确的完结/连载证据。缺少状态时应保持“未知”，不要自行约定未核实的 `status=某数字` 就等于完结。代码层的外部 `code=0` 也不代表原始详情一定包含你需要的每个字段。

当前详情缓存 TTL 为 3600 秒，没有对外暴露 `force_refresh` 参数。

## 11. 单集视频下载

```http
GET /api/duanju/download?item_id=9000000000000000101&definition=720p
```

| 参数 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| `item_id` | string | 是 | 无 | 非空单集 ID |
| `definition` | string | 否 | `720p` | 建议 `auto`、`1080p`、`720p`、`540p`、`480p`、`360p` |
| `playback_compat` | boolean | 否 | `false` | 在线兼容播放用，转换为 H.264/AAC；批量下载通常保持关闭 |
| `playback_stream` | boolean | 否 | `false` | 仅在 `playback_compat=true` 时生效，边转换边返回 |

清晰度规则：固定档位先选目标，再向低档查找，之后查高档；`auto` 按 `1080p → 720p → 540p → 480p → 360p` 查找。未知输入不会触发枚举校验错误，当前会以 720p 的优先顺序查找。上述档位均未命中时可回落到第一个可用源，**实际结果以响应头为准**。

```bash
# 输出到临时文件；成功后还需检查类型与媒体有效性，再改成最终文件名。
# --fail 使 HTTP 错误不会作为正常 MP4 正文写入。
curl --fail --show-error --get "$API_BASE/api/duanju/download" \
  --data-urlencode "item_id=$ITEM_ID" \
  --data-urlencode 'definition=720p' \
  --dump-header episode.headers.txt \
  --output episode.mp4.part
```

默认成功响应：

```http
HTTP/1.1 200 OK
Content-Type: video/mp4
Content-Disposition: attachment; filename="9000000000000000101_720p.mp4"
Content-Length: 12345678
X-Duanju-Definition: 720p
X-Duanju-Playback: original
```

正文是 **MP4 字节**，没有 `data.url` 或 `data.path`；保存位置由调用者选择。`original` 指保留原编码，不代表仍是加密内容，也不保证系统播放器支持该编码。

| 响应头 | 含义 |
|---|---|
| `Content-Type` | 成功为 `video/mp4`；错误通常为 JSON |
| `Content-Disposition` | 默认下载建议文件名 |
| `Content-Length` | 默认/非流式模式的响应视频字节数，不一定等于播放模型的 `size` |
| `X-Duanju-Definition` | 实际选用清晰度 |
| `X-Duanju-Playback` | 默认 `original`；非流式兼容 `h264-aac`；流式兼容 `h264-aac-stream` |
| `X-Playback-Mime`、`X-Playback-Duration` | 仅流式兼容模式的额外信息；该模式不保证默认下载的文件名和长度头 |

实现边界：默认下载接口先获取完整单集、处理后返回，服务端并非将 CDN 数据原样逐块转发；当前该路由没有 HTTP Range 断点续传处理。采集程序可以按“已完成单集”恢复，但不能假定失败单集支持按字节续传。调用一次只返回一集，不会自动合并整部剧。

## 14. 最小采集调用链与持久化建议

```text
new-releases / rank / search
  → 保存剧目 ID 与元数据
  → detail：补充详情与完结证据
  → catalog：获取当前剧集 ID 列表
  → 对照已完成记录，找出缺失单集
  → download：逐集保存并校验
  → 未更新齐：后续重新检查目录
  → 确认齐全：交给合并任务
```

建议分开记录以下数据；这是采集程序的数据设计，不是接口额外返回字段：

| 记录 | 建议字段 |
|---|---|
| 剧目 | `series_id`、剧名、类型、封面、声明集数、上线时间、首次发现时间、上次检查时间、完结证据 |
| 剧集 | `series_id`、`item_id`、目录顺序、集名、实际清晰度、本地路径、实际文件大小、下载状态、重试次数 |
| 任务 | 当前阶段、失败原因、下次重试时间、合并结果；仅在确认成功后推进状态 |

实际接入顺序：

1. 请求新剧第一页，检查 HTTP 和业务 `code`；按剧目 ID 去重保存。
2. 有下一页则立即继续分页；元数据扫描和耗时的视频下载分队列，避免下载期间游标过期。
3. 获取目录后按 `item_id` 去重，不重复下载已校验完成的集数。
4. 下载先写 `.part`，校验响应类型、非空文件和媒体有效性后再改名并标记完成。
5. 目录缺集或没有完结证明时保留观察状态；不能将接口返回空数组当作已完结。
6. 请求异常采用有上限的重试和退避；记录真实错误，避免失败后立即无限循环。
7. 每轮重新扫描第一页发现新剧；历史 ID 和单集完成记录负责去重与恢复。

每天 100 部、每部约 10GB 是吞吐目标，不是接口承诺。新剧和榜单的上游覆盖、分页可用性、下载带宽、缓存和失败重试都会影响结果；本次文档核对没有验证这个日产量。

## 16. 番茄小说书城推荐与换一批（上游接口）

来源：用户提供的《番茄小说推荐接口整理.md》。原文整理的是番茄 `app_name=novelread`、`aid=8662` 的两个上游接口，**不是新增的本地 `/api` 路由**。本节区分附件描述、当前源码和实际响应，不把推测当作确定契约。

### 16.1 请求地址与调用关系

```http
GET https://api5-normal-sinfonlineb.fqnovel.com/reading/bookapi/bookmall/tab/v:version/
GET https://api5-normal-sinfonlineb.fqnovel.com/reading/bookapi/bookmall/cell/change/v:version/
```

| 接口 | 用途 | 本次实测结论 |
|---|---|---|
| `bookmall/tab/v:version/` | 请求书城频道首屏和模块信息 | 有内容，但请求 `tab_type=16` 时实际填充的是 `tab_type=8`“找剧”频道 |
| `bookmall/cell/change/v:version/` | 按模块及会话请求另一批推荐 | 附件里的模块 ID 首次和续页都返回内容，详情见第 18 节 |

通常链路：

```text
tab 首屏
  → 检查实际返回的 tab_type，而不只看 HTTP 200
  → 从对应 tab/cell 提取 cell_id、bookstore_id、session_id、next_offset
  → change 换页，携带上一批的推荐上下文与过滤参数
  → 获取 series_id
  → 本地 catalog(book_id=series_id)
  → 本地 content/download(item_id=目录单集ID)
```

本次 `tab_type=16` 首屏和附件固定模块不是同一条经过首屏验证的链路：首屏回落到 tab 8 的模块；附件固定 cell 则可以独立请求成功。不能把两者拼成“tab 16 首屏明确返回该 cell”的结论。

### 16.2 请求参数

这是上游参数说明，不是已经穷举验证的必填参数清单。附件没有完整请求 URL/headers，本次补充了项目现有业务画像。

| 参数 | 请求表示 | 说明及证据边界 |
|---|---|---|
| `aid` | `8662` | 当前番茄畅读 App 标识，同时用于现有签名函数 |
| `app_name` | `novelread` | App 名称 |
| `device_id`、`iid` | 配对设备标识 | 由现有 `_with_device_identity` 在签名前注入；本文不保存真实值 |
| `device_platform`、版本等 | 业务画像字符串 | 本次分别测试现有 Android 7.2.9.32 画像和 iPhone 7.3.2.32 画像，不保证跨画像响应一致 |
| `tab_type` | 如 `16`、`8`、`38` | 请求频道；**返回频道可能与请求不同**，必须核对响应 |
| `offset` | 十进制整数 query | 首次测试为 `0`，续页用实际 `next_offset`；不是固定加某个数 |
| `cell_id` | ID 字符串 | 换页目标模块；优先取当前首屏的 `cell_id_str` 或 `cell_id` |

| `need_personal_recommend` | 本次 `1` | 附件解释为开启个性化推荐；本次确认携带后有响应，未证明它是必填或单独控制个性化效果 |
| `session_id` | 上页响应字符串 | 分页会话，原样回传；不要在多页请求中随意换设备或混用另一条链路的 session |

```json
]
```

`VideoSeries` 是这里的内容标识，**不是上游作品对象里数字型 `content_type` 的同一字段契约**。`rec_group_id` 在附件中为 JSON 数字，本次使用 Python 整数保持大 ID 精度；不要在 JavaScript 中先转成普通 `Number` 导致精度丢失。内存/数据库优先保存字符串，需要构造该上游数字表示时采用可保留大整数的序列化方式。

### 16.3 首屏真实返回层级

上游成功包裹为：

```json
{
  "code": 0,
  "message": "SUCCESS",
  "data": {
    "tab_index": 0,
    "tab_item": []
  },
  "log_id": "示例占位"
}
```

上例省略其他字段。注意上游叫 `message`，项目封装叫 `msg`。

| JSON 路径 | 类型/内容 | 说明 |
|---|---|---|
| `data.tab_item[]` | 频道对象数组 | 可同时返回频道导航和有内容的频道，不能只取第 0 项并假定命中目标 |
| `tab_item[].tab_type` | integer | 实际频道 ID；本次 tab 16 请求返回的有内容频道为 8 |
| `tab_item[].title` | string | 如“找剧”“真人剧”“漫剧” |
| `tab_item[].bookstore_id` | 大整数/ID | 现有封装转字符串作为 `plan_id`；只有有内容的 tab 才可能具备完整状态 |
| `tab_item[].session_id` | string | 首屏的换页会话状态 |
| `tab_item[].has_more`、`next_offset` | 可选分页字段 | 不同频道可能缺省；现有 discovery 的 offset 取自 cell |
| `tab_item[].cell_data[]` | 模块数组 | 目标模块含嵌套的内容数组 |
| `...cell_data[].cell_id`、`cell_id_str` | 模块 ID | 优先用字符串版避免精度问题 |
| `...cell_data[].next_offset` | integer | 本次首屏返回 `6`，换页时传入 |
| `...cell_data[].cell_data[].video_data[]` | 剧目推荐对象 | 注意 `cell_data` 有两层，不是直接 `data.items` |

不要递归搜到一个 `series_id` 就全部当作独立推荐：`video_detail.video_list[]` 内的每集也可能带同一个 `series_id`，会造成严重重复计数。

### 16.4 换一批真实返回层级

```json
{
  "code": 0,
  "message": "SUCCESS",
  "data": {
    "cell_view": {
      "cell_id_str": "7597343008509411390",
      "cell_data": []
    },
    "has_more": true,
    "next_offset": 6,
    "session_id": "使用实际返回值",
    "rank_version": "使用实际返回值"
  },
  "log_id": "示例占位"
}
```

| JSON 路径 | 说明 |
|---|---|
| `data.cell_view` | 本批次模块对象，检查 cell ID 是否正确 |
| `data.cell_view.cell_data[].video_data[]` | 本批次推荐作品，先按此路径提取，再按 `series_id` 去重 |
| `data.next_offset` | 下一页位置，本次从 `6` 推进到 `12` |
| `data.has_more` | 是否有更多内容；本次为 `true` 不代表无限或全站覆盖 |
| `data.session_id` | 下一次请求使用的会话状态，原样回传 |
| `data.rank_version` | 本次响应存在此字段；没有验证推荐换页是否必须回传，不与榜单协议强行混用 |

### 16.5 推荐作品字段与 ID 区别

同一族接口可返回“外层字段完整”和“信息集中在 `video_detail`”两种形态。本次附件固定模块主要是后一种。

| 字段/路径 | 含义 | 采集时如何处理 |
|---|---|---|
| `series_id` | 作品/整部剧 ID | 剧目去重主键；可传给项目 `catalog?book_id=` |
| `vid` | 外层视频入口 ID | **本次固定模块中可为空**，不能假定总可直接下载 |
| `recommend_group_id` | 响应中的推荐组 ID | 与请求 `rec_group_id` 对应的上下文来源；不要误写成响应必有 `rec_group_id` |
| `video_detail.first_vid` | 详情中的首集 ID | 外层 `vid` 为空时可取它作首集入口；完整采集仍走目录 |
| `video_detail.series_title` | 剧名 | 外层 `title` 缺失时回落 |
| `video_detail.series_cover` | 封面 | 外层 `cover` 不可用时回落 |
| `video_detail.series_intro` | 简介 | 外层 `video_desc` 不可用时回落 |
| `video_detail.episode_cnt` | 上游集数 | 与目录核对，不等于完结标记 |
| `video_detail.content_type` | 数字内容类型 | 本次样本为 `1004`；不要与请求中的字符串 `VideoSeries` 混淆 |
| `video_detail.video_list[]` | 内嵌剧集信息 | 本次存在，但不将它保证为永久完整目录，优先用 `/catalog` |
| `video_detail.status`、`series_status` | 上游状态值 | 本次存在，枚举含义未验证，不猜测哪个数字表示完结 |
| `recommend_info` | 推荐上下文 | 作为不透明上游数据处理，本文不定义其内部契约 |

**三个 ID 不保证相等。** 本次一条真实记录中：

```text
series_id          = 7680552155941456958
recommend_group_id = 7680657333269040152
video_detail.first_vid = 7680657301639810072
```

因此不能统一写成 `rec_group_id = item_id = series_id`。附件中的 `filter_id_map.item_id` 是请求结构；本次顶层推荐作品主要返回 `vid` / `video_detail.first_vid`，不是固定的 `item_id` 字段。

## 17. 现有项目推荐接口（可直接调用）

当前项目已经封装真人剧和漫剧的推荐首屏/换页，分别使用上游 tab 38/32。本次只验证真人剧；**没有新增 tab 16、tab 8 的本地路由，也没有把附件新字段自动接入产品页面**。

### 17.1 推荐首屏

```http
GET /api/duanju/discovery?content_type=drama
```

| 参数 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| `content_type` | string | 否 | `drama` | `drama` → 真人剧 tab 38；`manju` → 漫剧 tab 32 |
| `filter_ids` | string | 否 | `""` | 已展示 `series_id` 的逗号分隔队列 |
| `selected_items` | string | 否 | `""` | 分类标识，如 `cate_20`，应取返回 `categories[].id` |

```bash
curl --fail-with-body --get "$API_BASE/api/duanju/discovery" \
  --data-urlencode 'content_type=drama'
```

`data` 返回字段：

| 字段 | 类型 | 含义 |
|---|---|---|
| `tab_type` | string | `"38"` 或 `"32"` |
| `items` | array | 第 4 节的剧目标准化对象；此来源可能补充非空 `rank_tags` |
| `cell_id` | string | 目标推荐模块 |
| `next_offset` | integer | 换页用的 offset |
| `has_more` | boolean | **当前首屏实现固定输出 `true`**，不是上游尚有内容的严格证明 |
| `session_id` | string | 下一页会话 |
| `plan_id` | string | 从当前 tab 的 `bookstore_id` 提取 |
| `filter_ids` | string | 后端累积的 `series_id` 队列，后续原样回传 |
| `tab_list` | array | `{ "tab_type": 38, "title": "真人剧" }` 等导航项 |
| `categories` | array | 分类项，含 `id`、`name`、`group` |
| `rank_boards` | array | 从推荐标签提取的入口，每项含 `label`、`schema`；不是第 5 节的 `boards` 标识表 |
| `selected_items` | string | 当前分类选择 |
| `raw` | object | 原始上游响应，路径见第 16 节 |

首屏已解析出剧目仍需检查 `cell_id`、`plan_id`、`session_id` 非空、`next_offset >= 1`，才能调用现有换页路由。

### 17.2 推荐换一批 / 换页

```http
GET /api/duanju/discovery/more?content_type=drama&cell_id=...&offset=6&session_id=...&plan_id=...&filter_ids=...
```

| 参数 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| `content_type` | string | 否 | `drama` | 与首屏一致，`drama` 或 `manju` |
| `cell_id` | string | 是 | 无 | 首屏返回值，非空 |
| `offset` | integer | 是 | 无 | 上页 `next_offset`，必须 `>= 1` |
| `session_id` | string | 是 | 无 | 上页返回的会话，非空 |
| `plan_id` | string | 是 | 无 | 当前链路的方案 ID，非空 |
| `filter_ids` | string | 否 | `""` | 上页返回的完整过滤队列，避免自行换成视频 ID |
| `selected_items` | string | 否 | `""` | 与首屏一致 |

```bash
# 以下变量均替换为上一页的 data 字段，不要把示例 ID 当作固定配置。
CELL_ID='上一页data.cell_id'
NEXT_OFFSET='6'
SESSION_ID='上一页data.session_id'
PLAN_ID='上一页data.plan_id'
FILTER_IDS='上一页data.filter_ids'
SELECTED_ITEMS=''
curl --fail-with-body --get "$API_BASE/api/duanju/discovery/more" \
  --data-urlencode 'content_type=drama' \
  --data-urlencode "cell_id=$CELL_ID" \
  --data-urlencode "offset=$NEXT_OFFSET" \
  --data-urlencode "session_id=$SESSION_ID" \
  --data-urlencode "plan_id=$PLAN_ID" \
  --data-urlencode "filter_ids=$FILTER_IDS" \
  --data-urlencode "selected_items=$SELECTED_ITEMS"
```

成功 `data` 含 `tab_type`、`items`、`next_offset`、`has_more`、`session_id`、`cell_id`、`plan_id`、`filter_ids`、`selected_items`、`rank_boards`、`raw`，类型与首屏相同；没有首屏的 `tab_list` 和 `categories`。`has_more` 来自换页上游响应；会话缺失时当前实现保留请求中的会话值。

当前封装限制：

- 这些接口不使用第 4 节的短 `cursor`，而是传多个分页参数，不要混用两种分页协议。
- 缓存 TTL 为 1800 秒，相同参数重复请求可能直接命中缓存；换页应使用新状态。
- 没有对外开放 `tab_type`、`need_personal_recommend`、`rec_filter_info_list`、`recommend_extra` 参数。把这些参数随意附加到本地 URL，不代表后端会转发给上游。
- 当前 discovery 没有将设备绑定信息传给下一页；本次路由测试使用同一设备固定适配器成功，**没有证明生产环境随机换设备后分页依然稳定**。
- 当前解析器在换页无内容时返回 HTTP 502 / `code=-4`，不会把它标准化为成功的空末页。因此不能依据现有路由描述里的“无限翻页”断言永远有内容。

## 18. 推荐接口可用性实测（2026-09-14）

### 18.1 测试方式

使用项目现有 `PureSignedClient.signed_get` / `signed_post`、`generate_all_headers` 和 `_with_device_identity`：`device_id` 与 `iid` 在签名前配对注入。推荐请求使用 `aid=8662`，目录使用现有路由的 `aid=1967`。没有手工复用旧签名，也没有用模拟上游响应代替网络结果。

设备池使用临时目录中的隔离副本；同一设备完成本次请求，未启动项目后台补池调度。为限制请求量，探测不执行默认的多轮设备切换重试。推荐本地封装是在进程内调用实际路由函数、接固定设备的真实签名网络适配器；没有启动监听端口或测试桌面安装包。

共 11 次业务上游请求：9 次推荐请求（含一个修正前的探索请求），1 次目录，1 次播放模型。结果记录时间为北京时间 16:29:57–16:32:39，具体耗时见 [脱敏结果 JSON](examples/2026-09-14-recommendation-probe.json)。原始响应、设备信息、密钥、签名和 session 未放入文档或结果文件。

### 18.2 结果

下表所有网络请求均为 HTTP 200、上游 `code=0`；是否满足业务目标另行判断。

| 测试 | 结果 | 结论 |
|---|---|---|
| 附件 tab 接口，Android 7.2.9.32，`tab_type=16` | 实际有内容的 tab 为 `8`“找剧”，6 个不同剧目 ID | **接口有内容，但目标频道未命中** |
| 同一 tab 请求，切换现有 iPhone 7.3.2.32 画像 | 同样返回 tab `8`，8 个不同剧目 ID | 不能把 tab 16 当作已验证的稳定频道 |
| 当前 tab 38 / c 域名 `/tab/v` 对照请求 | 真人剧 tab `38`，6 部 | 当前真人剧首屏可用 |
| 附件 `cell=7597343008509411390`、`plan=7597343072904560702`、tab 16、offset 0 | 6 部；`next_offset=6`；`has_more=true` | **附件固定模块当前可用** |
| 同一固定模块，传完整非空曝光记录、上一页 session、offset 6 | 又返回 6 部，与首批重叠 0 部；`next_offset=12` | 当前两页成功，获得 12 个不同剧目 |
| 从实际 tab 8 首屏提取 cell/plan，再换页 | 首屏 6 部、换页 6 部，重叠 0 部；offset 推进到 12 | 实际返回频道的首屏→换页链路可用 |
| 当前 `/api/duanju/discovery` 路由函数，真人剧 | 项目 HTTP 状态 200 / `code=0`，6 部，offset 6 | 现有首屏构造和解析可用 |
| 上述结果调用 `/api/duanju/discovery/more` 路由函数 | 项目状态 200 / `code=0`，6 部，与首屏重叠 0 部，offset 12 | 同设备条件下现有换页构造和解析可用 |
| 固定模块中的 1 部剧 → `/catalog` | 125 条目录，125 个不同单集 ID | 推荐 `series_id` 能接现有目录链路 |
| 该目录首集 → `/content` | 5 个带 URL 和处理参数的源：360p/480p/540p/720p/1080p | 播放模型可用；**未验证视频字节下载** |

用于关联目录的真实样本：

```text
剧名：一年升一境凡人修仙之外门杂役
series_id：7664807332483697726
标准化 first_vid：7664808905486126104
列表声明 episode_count：125
目录条数 / 去重后条数：125 / 125

```

该结果只说明本次样本的推荐 ID、目录和播放模型可以串联；不据此保证所有推荐都可下载、全部已完结或每天能发现 100 部新剧。

### 18.3 对附件说法的修正与未验证项

1. **`tab_type=16`：**两种现有画像均返回 tab 8，不能仅凭 `SUCCESS` 宣布原 tab 16 复现成功。附件缺少完整画像与上下文，暂不判断是版本、频道配置还是其他参数导致。
2. **`rec_group_id` 与 `item_id`：**响应实际使用 `recommend_group_id`；有的记录它与首集 ID 不同。外层 `vid` 也会为空，应先检查 `video_detail.first_vid` 或取目录。
3. **去重效果：**传完整曝光记录的续页与首批没有重叠，但本次没有控制变量实验，不能证明是 `filter_ids` 或 `rec_filter_info_list` 中某一项单独生效，更不能保证以后无重复。采集端仍需按 `series_id` 去重。
4. **探索请求的修正：**初次构造固定模块的曝光记录时，外层 `vid` 为空导致 `item_id` 为空；该请求虽返回 6 条，但不作为有效曝光验证。之后使用详情 `first_vid` 补全 6 条非空 item ID，重新请求成功；脱敏结果保留了这一区别。
5. **`recommend_extra`、`session_uuid`、其他 `change_type`：**未验证。附件中的 Base64、停留时长、消费时长等解释保留为待核实说明，不能当作当前已实现的推荐算法。
6. **推荐不等于上新：**这两个接口用于扩充候选剧目来源；要做自动追新，仍需结合第 4 节时间范围、历史 ID、目录和完结证据。它们不是全站导出接口。

本次完成文档整合和有边界的实测，没有修改生产签名、API 路由或自动追剧调度逻辑。
