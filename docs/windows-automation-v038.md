# v0.3.8 Windows 自动追剧修复

自动追剧下载完成后，旧实现传入 `mode: None`、`transcode_h264: false`，只允许无损拼接。遇到各集分辨率、帧率或音频配置不同就报“输入媒体参数不一致，需要开启 H.264 转码”。

- 新的正片和首集 Shorts 合并使用 `MergeMode::Auto`：兼容媒体直接拼接，仅音频不同时保留视频并统一音频，视频不兼容时逐集 H.264 转码。Windows 沿用 NVENC 检测及 CPU 回退。
- 自动追剧的旧失败/中断任务重试时，重新校验原文件并将合并模式更新为 Auto，原任务 ID、集数、文件快照、质量和输出路径保留。去重键和请求一起原子持久化。手动合并的重试仍保留用户指定模式。
- 分离背景音乐与语音字幕共用音频预处理：检测音轨、明确选择第一条音轨、重建缺失时间戳、统一采样，并允许长音频的 RF64 WAV。输出进度实时反馈且支持暂停/取消；FFmpeg 标准错误并行读取，只保留最后 8 KiB，避免阻塞与无限增长。
- 音频失败提示区分无音轨、磁盘空间、权限、文件缺失和解码损坏，附带受限长度的 FFmpeg 诊断。未取得用户原始失败视频，不能确认其具体音轨故障；无音轨及正常中文路径样本已验证。
- 后台显示中文阶段、当前集下载/校验状态、独立阶段百分比及计划重试时间；“下载已完成 152/152 集”与合并、音频、AI 阶段进度分别显示。

## 本地验证

- 前端：353 项通过。
- Windows Rust：234 项通过、3 项忽略。含旧合并请求重试、不同分辨率/帧率合并、音频不一致与无音轨输入、真实中文路径音视频的 WAV 解码、取消与错误诊断。
- 回归测试先在修复前运行，确认旧请求模式、笼统音频错误及后台显示测试失败；修复后通过。

升级后，在自动追剧页面对之前失败的任务点击“重试此任务”，并确保后台已启动或继续运行。已校验的剧集会复用，无需重新下载全部剧集。
