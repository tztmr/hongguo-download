## 实测后调整

重复拼接 60 段 1 秒 AAC：ffprobe 容器音轨时长 60.021333 秒，解码 PCM 实际样本时长 61.44 秒。时间戳完整并不保证解码样本时长正确，不能仅凭容器时间选择整段音视频复制。

智能模式因此调整为：兼容画面直接复制；多集音轨逐集解码为精确时长的 PCM，最终只编码一次 AAC。无音轨或合适的单文件可完整复制。“仅无损合并”保留显式选择，但样本校验失败必须阻止发布。最终校验新增音频解码样本计数，读取过程保持固定内存。

新增真实 FFmpeg 回归覆盖 31 分钟 / 60 集、混合规格、短音轨、音频中途缺口、硬件编码中途失败后统一软件回退、仅无损模式阻止 AAC 样本累积误差。不能据此断言用户既有视频的口型问题已经修复，仍需实际素材确认。

## 同轮转写故障修复

用户追加报告“语音转写执行失败”。本机失败任务使用已安装 runtime 2、Whisper small，对合并视频转写。

复现得到三个独立原因：
1. 自动选择 MPS，Whisper 加载稀疏 alignment_heads 时 Torch 2.5.1 抛出 SparseMPS NotImplementedError。
2. CPU 路径中 Whisper 按命令名执行 ffmpeg，GUI 的 PATH 不含打包媒体工具，抛出 FileNotFoundError。
3. verbose=False 仍打印 Detected language: Chinese，原本的严格 JSON 行解析会误报协议错误。

桌面端为转写固定 CPU，设置已验证 FFmpeg 所在目录加系统目录的 PATH，并仅兼容已知且长度/字符受限的语言提示行。其他输出仍要求合法协议 JSON。保留 runtime / 模型版本，不要求用户重新下载。

使用失败视频第 30 秒起的 15 秒对白、原本已安装 runtime 2 和 small 模型进行实际验证，成功生成 15 条中文字幕；未重跑整季。额外加入原生 run_worker 调用路径的手动集成测试。

转写修复合入后的最终检查：Rust 152 通过、4 手动测试默认忽略，格式与 clippy 通过。已单独执行现有 runtime 的原生转写集成测试并通过。前端保持 114 测试通过。
