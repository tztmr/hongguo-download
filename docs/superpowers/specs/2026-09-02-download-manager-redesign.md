# 红果下载 UI 与批量下载管理设计

日期：2026-09-02

## 目标

重做桌面端 UI，并将现有单集串行队列升级为可持久化、可调并发、按剧分组的批量下载管理。用户可以在浏览短剧时快速批量选集，也可以在独立下载管理页集中查看、暂停、继续、重试和清理任务。

## 已确认的产品决策

- 下载管理采用“下载中心优先”的一级页面结构。
- 任务列表按剧分组，每部剧只显示一行；右侧固定显示该剧的逐集详情。
- 任务与历史在应用重启后保留。重启前正在下载的集恢复为等待状态，并从该集开头重新下载，不做字节级断点续传。
- 暂停不会中断正在下载的一集；当前集完成后停止启动后续集。
- 全局并发默认 5，可调整为 1–10，不同剧共享同一个并发额度。
- 删除任务与清理已完成只删除任务记录，不删除磁盘上的 MP4 文件。
- 使用 TypeScript 任务协调器和本地持久化；Rust/Tauri 继续负责单集下载、解密、文件写入和进度通知。

## 范围

### 本次包含

- 发现、搜索、榜单、详情选集和下载管理页的统一视觉重做。
- 逐集勾选、全选、反选、按起止集数选择。
- 多部剧连续加入下载队列，重复集过滤。
- 剧级任务分组与逐集状态明细。
- 全局并发调度，默认 5、可调 1–10。
- 剧级和全局暂停/继续。
- 单集失败重试、剧级重试全部失败项。
- 删除任务、移除等待或失败单集、清理已完成记录。
- 已完成文件定位和下载目录打开。
- 队列、并发设置和完成历史本地持久化。

### 本次不包含

- 应用关闭后继续在后台下载。
- 正在下载文件的立即取消。
- HTTP Range 字节级断点续传。
- 删除下载记录时同步删除磁盘视频。
- SQLite、云同步或跨设备任务同步。

## 架构

### 组件边界

1. `download-manager` 领域模块
   - 定义批量任务、单集任务和状态派生规则。
   - 提供创建任务、重复过滤、暂停、继续、重试、移除、清理等纯函数。
   - 提供可独立测试的并发调度选择函数。

2. 下载协调 Hook / Provider
   - 持有运行时状态和活动 Promise 集合。
   - 监听 Tauri 下载进度事件，并把事件映射到具体单集。
   - 在空闲并发槽出现时启动等待中的单集。
   - 将状态变化节流写入本地存储。

3. Tauri 下载适配层
   - 继续调用现有 `download_episode` 命令。
   - 每个活动单集对应一次命令调用。
   - 继续消费 `download-progress` 事件和完成结果。

4. 页面组件
   - 浏览区域负责选剧和选集，不直接维护下载执行状态。
   - 下载管理页只通过任务协调器公开的命令操作任务。
   - UI 组件只消费派生统计，不重复实现状态规则。

### 数据流

```text
发现/搜索/榜单
  -> 选择一部剧并加载目录
  -> 选择多集
  -> enqueueBatch(series, episodes)
  -> 合并到 DownloadBatch
  -> 调度器按全局并发额度选择可运行单集
  -> Tauri download_episode
  -> download-progress 事件更新单集进度
  -> 完成或失败状态写回任务
  -> 重新填充空闲并发槽
  -> 持久化任务快照
```

## 数据模型

```ts
type DownloadItemStatus =
  | "queued"
  | "running"
  | "done"
  | "error";

type DownloadItem = {
  id: string;
  itemId: string;
  episodeIndex: number;
  episodeTitle: string;
  definition: string;
  status: DownloadItemStatus;
  percent: number;
  received: number;
  total?: number;
  path?: string;
  error?: string;
  addedAt: number;
  completedAt?: number;
};

type DownloadBatch = {
  id: string;
  bookId: string;
  title: string;
  cover: string;
  paused: boolean;
  items: DownloadItem[];
  createdAt: number;
  updatedAt: number;
  removeWhenIdle?: boolean;
};

type DownloadManagerState = {
  version: 1;
  concurrency: number;
  globallyPaused: boolean;
  batches: DownloadBatch[];
};
```

批量任务的“下载中、等待中、已完成、失败”不单独持久化，而是根据内部单集状态派生，防止父子状态不一致。

## 调度规则

- 全局活动数小于 `concurrency` 时才启动新单集。
- 全局暂停或所属剧暂停时，不启动该剧的等待项。
- 在可运行剧之间采用轮转选择，避免一部长剧长期占满全部并发槽。
- 单集开始前先将状态改为 `running`，并登记活动 Promise，避免重复启动。
- 单集完成后记录路径、实际清晰度和完成时间；失败后保留错误原因。
- 任一活动 Promise 结束都会触发下一轮调度。
- 调低并发数不会中断已开始的单集；等待活动数自然下降到新上限后再启动新任务。
- 暂停不会改变运行中单集状态；运行项完成后不再补充该剧或全局的后续任务。
- 删除含运行项的剧级任务时设置 `removeWhenIdle`，提示“当前集完成后移除任务”；活动项结束后仅删除记录，不删除生成的文件。

## 持久化与恢复

- 使用带版本号的本地存储键保存 `DownloadManagerState`。
- 任务、历史、全局暂停状态和并发设置均持久化。
- 频繁进度事件只更新内存；持久化写入节流，完成、失败、暂停和删除等关键状态立即写入。
- 应用启动时校验数据形状并限制并发值到 1–10。
- 恢复时把所有 `running` 单集转换为 `queued`，进度归零并清除上次会话的瞬时接收字节；已完成项保留路径和完成时间。
- 下载重启会覆盖同名 `.part` 临时文件并从头下载，不把旧临时文件误认为完成文件。
- 若存储内容无法解析，先把原始字符串复制到带时间戳的备份键，再使用空队列启动，并在 UI 显示恢复提示。

## 页面与交互

### 全局框架

- 左侧导航：发现、搜索、榜单、下载管理。
- 下载管理入口显示未完成集数徽标。
- 顶部区域统一页面标题、搜索和内容类型切换。
- 使用炭灰色层级背景；红色只用于主操作、进度和异常提示。

### 浏览与选集

- 中间区域展示剧集卡片，右侧固定显示封面、元信息和目录。
- 目录提供逐集勾选、全选、反选和起止集数选择。
- 主按钮显示“加入下载队列（已选 N 集）”。
- 入队成功后保留当前浏览位置并显示结果提示：新增数量、跳过重复数量。
- 同一 `bookId + itemId` 只允许一个未移除记录；已完成记录仍存在时再次入队视为重复。

### 下载管理

- 顶部统计卡展示下载中、等待中、已完成和失败的单集数量。
- 顶部全局操作：全部暂停/继续、清理已完成、打开目录、并发数选择。
- 左侧剧级任务列表展示封面、剧名、完成数/总数、整体进度、派生状态和更多操作。
- 选中一部剧后，右侧固定详情展示每一集的状态、进度、错误和可用操作。
- 剧级操作：暂停/继续、重试全部失败项、移除任务。
- 单集操作：失败项重试、等待或失败项移除、已完成项定位文件。
- “清理已完成”只移除所有单集均完成的剧级记录；混合状态任务不被清理。

### 小窗口行为

- 正常桌面宽度使用左侧任务列表 + 右侧固定详情。
- 宽度不足时压缩统计卡和操作区，但任务名称保持省略号，不横向挤坏表格。
- 更窄窗口中逐集详情改为覆盖式面板，可返回任务列表。

## 错误处理

- 单集失败不阻塞同剧或其他剧的任务。
- 单集保留面向用户的错误摘要；详情区域可查看完整错误。
- 剧级任务显示失败数量，并提供“重试失败项”。
- 本地 API 或设备池不可用时，新启动项进入失败状态；已在等待的其他项不会被批量错误覆盖。
- 持久化失败时显示非阻塞警告，当前会话仍可继续下载，但明确提示重启后可能无法恢复。
- 文件定位失败时只提示路径不可用，不改写已完成状态。

## 测试与验收

### 自动化测试

- 新批量任务按剧分组并正确过滤重复集。
- 同一剧追加新集时合并到原任务而不是新增行。
- 调度器从 1–10 并发设置中严格遵守上限，默认值为 5。
- 多部剧轮转取任务，不让单部长剧独占全部新槽位。
- 全局暂停和剧级暂停均阻止后续项启动，运行项可正常完成。
- 调低并发不取消运行项，后续启动遵守新上限。
- 失败项可以单集或整剧重试。
- 删除运行中任务使用延迟移除语义，且不删除文件。
- 持久化恢复把 `running` 转换为 `queued`，保留 `done` 和设置值。
- 损坏持久化内容会备份并回退为空状态。

### 构建与渲染验证

- TypeScript 与 Vite 构建通过。
- Tauri Rust 检查或构建通过，确认现有下载命令接口未被破坏。
- 浏览器预览验证发现页、批量选集和下载管理的布局与交互。
- 验证桌面宽度和一个窄窗口宽度，不出现遮挡、横向滚动陷阱或不可点击控件。
- 验证无框架错误覆盖层，控制台无相关错误或警告。
- 在可用的本地 API 环境中执行至少一次真实单集下载，确认进度事件、完成路径和任务状态闭环；若上游或设备环境不可用，必须明确报告此运行时层未验证。

## 完成标准

- 用户可从任意剧集详情一次加入多集，并继续浏览其他剧。
- 下载管理按剧分组，右侧可查看和操作逐集状态。
- 默认并发为 5，调整范围为 1–10，运行时严格遵守设置。
- 暂停、继续、失败重试、任务移除、完成记录清理和文件定位符合本文语义。
- 应用重启后任务与历史可恢复，不错误显示旧会话中的运行状态。
- 删除记录不会删除磁盘 MP4。
- 自动化测试、构建和渲染验证结果都有可复核证据。
