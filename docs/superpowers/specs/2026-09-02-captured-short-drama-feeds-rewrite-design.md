## 用户可见目标

1. 新剧监听只显示北京时间今天上线的内容。
2. 一级类型只有 `真人剧`、`漫剧`、`AI剧`；默认打开真人剧。
3. 二级分类由当前类型的剧目标签动态生成，至少规范化 `校园`、`古风`，空标签归 `其他`；其余有效标签原样保留。
4. 每 5 分钟完整刷新当前类型，首次加载不通知，后续新增项目合并通知。
5. 应用不设置 10 页、20 条、99 条或 100 条总量上限；分页只在上游 `has_more=false` 时正常结束。
6. 当天已发现项目按日期和类型持久化、去重并合并；刷新失败保留旧结果。
7. 榜单展示抓包验证的 8 个榜单，并可从首页连续翻到上游自然结束。

## 架构

新增 `core/duanju_feeds.py` 作为纯协议层，负责：

- 番茄 7.3.2.32 动态设备画像和 URL 查询参数；
- 真人剧日志响应解析；
- 漫剧/AI 新榜及 8 榜响应解析；
- 安全分页状态和停滞检测需要的字段；
- 剧目字段、来源类型与标签规范化。

`endpoints/duanju.py` 继续负责签名客户端调用、设备复用、缓存、短游标和 FastAPI 错误转换。前端只处理后端短游标，不持有上游 session、设备或 filter IDs。

## 新剧监听

后端保留：

```text
GET /api/duanju/new-releases?type=playlet|comic_series_rank|ai_playlet&cursor=&limit=20
```

- `playlet` 直接分页读取当天日志；列表自带上线时间、播放和收藏数据，不逐剧请求详情。
- `comic_series_rank`、`ai_playlet` 分别翻完新剧榜。每个上游页面用一次批量详情请求取得 `create_time`，过滤上海当天；不逐条串行请求。
- 聚合器没有总页数上限，但拒绝重复分页状态、未前进 offset 和 `has_more=true` 的空停滞页，避免死循环。
- API 每次最多返回 `limit` 条只是传输分页大小，不是总量上限；多取结果放入短游标 buffer。
- 类型只由请求所用的上游 selector 决定。`content_type=1004`、`vertical` 和 `ai_usage_type` 都不能用来互相转换类型。

前端刷新当前类型时连续消费所有后端页直至 `has_more=false`，合并到当天该类型的持久化结果。切换类型独立加载和存储。页面可按动态二级分类过滤，且展示“已收录 N 部”和刷新状态。

## 分类规则

把 `category`、`sub_title`、`sub_title_list` 中的有效标签按常见分隔符拆开并去重：

- 包含 `校园`、`青春` 的标签统一显示为 `校园`；
- 包含 `古风`、`古装`、`古代`、`古言`、`宫斗`、`仙侠`、`武侠` 的标签统一显示为 `古风`；
- 其他非空标签原样保留；
- 无有效标签显示为 `其他`。

一个剧目可以属于多个二级分类。二级分类只影响前端筛选，不改变上游扫描范围。

## 榜单

固定榜单目录：推荐榜、热播榜、臻果榜、预约榜、新剧榜、热搜榜、必看榜、收藏榜。固定 `selected_items=all`，前端移除一级范围和分类参数，避免混用未在本抓包验证的协议。

后端榜单 API 使用短游标：

```text
GET /api/duanju/rank?board=ranklist_hot_sc&cursor=&limit=20
```

游标绑定榜单和上海日期，保存上游 offset、session、rank version、设备、最近 200 个去重 ID、buffer 和 `has_more`。桌面端只追加标准剧目，编号连续，不再使用 `maxItems: 100`。

## 错误与安全

- 上游失败返回脱敏 502；游标过期、跨类型或跨榜单返回 400。
- 刷新失败不清空现有监听或榜单列表。
- 应用关闭期间不承诺系统级后台监听；重新打开后会重新扫描当前上游窗口并合并当天持久化记录。
- 不记录完整上游 URL、session、设备、Cookie、签名或推荐追踪字段。
