# 红果下载：媒体处理与 YouTube 上传设计

日期：2026-09-02

## 目标

在现有 macOS Tauri 下载器中扩展一套可恢复的媒体处理与 YouTube 上传流程：

1. 按集数顺序合并已下载视频，并可选转为 H.264。
2. 使用 AI 分离人声和背景音乐，生成去背景音乐视频。
3. 提取可用字幕轨，或使用 Whisper 从对白重新生成 SRT。
4. 安全导入 Google Desktop OAuth 凭证，授权后上传已合并视频到 YouTube。
5. 把下载、媒体处理、上传和系统通知整合到同一个可追踪的下载管理流程。

## 与现有规格的关系

本设计是以下现有规格的增量扩展，不改变已确认的下载语义：

- `2026-09-02-download-manager-redesign.md`：继续保留按剧分组、默认 5 并发、可调 1–10、只删记录不删文件等规则。
- `2026-09-02-new-releases-settings-categories-design.md`：继续保留下载完成通知、今日新剧监听通知、设置持久化和安全边界。

本阶段的原生交付目标与当前项目一致：优先验证 macOS ARM64。Windows、macOS Intel、签名和公证不在本规格的完成承诺内。

## 已确认的产品决策

- `合并视频`、`分离背景音乐`、`提取字幕`是三个相互独立的功能和按钮。
- 合并时弹窗询问是否转为 H.264，默认选择转码。
- 背景音乐分离使用 AI 人声/伴奏分离，不是单纯导出原音轨。
- 已有合并视频时，音乐分离和字幕提取均弹窗选择“逐集处理”或“处理合并视频”。
- 字幕先尝试导出可提取字幕轨；无字幕轨时使用本地 Whisper 生成 SRT。
- 已烧录在画面中的字幕不做 OCR。Whisper 输出来自语音识别，可能与画面字幕不完全一致。
- Demucs 默认模型为 `htdemucs`；Whisper 默认模型为 `small`，设置中可选择已支持模型。
- AI 运行环境和模型首次使用时按需下载；基础应用不因没有 AI 组件而影响普通下载。
- FFmpeg 和 ffprobe 随应用打包，不要求用户额外安装。
- 现有 Python API 打包为独立可执行后端，不依赖用户电脑的 Python 或 pip 依赖。
- YouTube 只上传已合并的完整视频，不批量上传逐集文件。
- 上传时默认选择“去背景音乐版”，可切换为原音频合并版。
- YouTube 标题、简介和封面默认继承下载记录，上传前可编辑。
- YouTube 默认公开；默认不面向儿童；AI 剧默认声明包含合成内容，上传前必须确认。
- SRT 只保存在本地，不上传 YouTube 字幕。
- Google OAuth 凭证导入应用私有配置目录，刷新令牌保存在 macOS 钥匙串，任何凭证都不得进入安装包、日志或代码仓库。

## 总体架构

采用“Tauri/Rust 任务协调 + 内置媒体工具 + 按需 AI 工作进程 + 独立 YouTube 客户端”：

```text
下载管理 UI
  -> MediaJobManager (Rust)
       -> 内置 ffprobe/ffmpeg：检查、合并、转码、封装
       -> AI Worker：Demucs 分离、Whisper 识别
       -> YouTube Client：OAuth、断点上传、封面设置
  -> 持久化任务快照
  -> Tauri 进度事件和 macOS 通知
```

### 组件边界

1. **MediaJobManager**
   - 定义媒体任务、状态转移、排队、取消、重试和持久化。
   - 与现有下载调度器独立；媒体处理不占用普通下载并发额度。
   - 默认一次只运行一个重型媒体任务，其他任务排队，避免 CPU、GPU 和内存争用。

2. **FFmpeg 适配层**
   - 只通过应用资源目录中的已校验 FFmpeg/ffprobe 执行，不隐式回退到 `PATH`。
   - 封装参数构造、进度解析、取消和错误脱敏，不让 UI 拼接命令行。

3. **AI Worker**
   - 与现有 FastAPI 服务分离，使用结构化标准输出报告阶段、进度和结果。
   - 单个任务的崩溃不应使现有本地 API 退出。
   - AI 运行环境和模型放在 Tauri 应用数据目录，不修改应用包内容。

4. **YouTube Client**
   - 复用已验证的 Rust OAuth、钥匙串令牌保管、可恢复上传和错误映射模式。
   - 与媒体任务共享进度事件格式，但不与下载 API 耦合。

5. **自包含 API 后端**
   - 把当前 Python API 打包为独立 sidecar 可执行程序。
   - 产物不得调用系统 Python，不得提示用户执行 `pip install`。

## 媒体任务模型与恢复

任务至少保存：

- 任务 ID、任务类型、剧目 ID 和标题。
- 处理范围：逐集或合并视频。
- 输入文件快照、输出路径和配置参数。
- 状态：`queued`、`running`、`completed`、`failed`、`cancelled`、`interrupted`。
- 阶段、百分比、开始/完成时间、可脱敏错误代码和错误摘要。
- YouTube 上传任务额外保存可恢复会话信息和已确认偏移。

持久化使用带版本的应用数据文件，通过临时文件加原子替换写入。重启恢复规则：

- 已完成任务和输出继续保留。
- 中断的合并、转码、音乐分离和字幕任务标记为 `interrupted`，可一键从头重试，不伪装成已从中间恢复。
- YouTube 上传优先查询服务端已接收范围后续传；会话过期则提示从头开始。
- 任务恢复前重新检查输入文件的存在性、大小和修改时间；输入已变更时不盲目续传。

所有任务在唯一临时目录中工作。仅当输出文件存在、可由 ffprobe 读取且符合预期流和时长后，才原子移动到正式路径。取消只清理本任务的临时产物，永不删除原始下载文件。

## 合并视频

### 交互

已完成的剧级下载批次显示 `合并视频`。弹窗显示：

- 按 `episodeIndex` 排序的包含集数。
- 输出名称和目录。
- `转为 H.264`开关，默认开启。

输出已存在时必须选择覆盖、另存或取消；默认不覆盖。

### 处理规则

1. ffprobe 预检查每一集的容器、视频/音频编码、分辨率、帧率、时间基、声道和采样率。
2. 未选 H.264 时，只对可安全拼接的流使用 concat demuxer + stream copy。
3. 参数不兼容时禁止无转码合并，明确提示必须启用 H.264，不生成可能损坏的文件。
4. H.264 模式优先使用 `h264_videotoolbox`，初始化或运行失败时回退到 `libx264`；音频统一为 AAC。
5. 完成后检查可读取性、时长偏差和音视频流，验证通过才入库。

## 分离背景音乐

`分离背景音乐`是独立任务：

- 无合并视频时直接逐集处理。
- 已有合并视频时弹窗选择逐集或合并视频。
- 默认使用 Demucs `htdemucs` 的人声/伴奏两轨模式。
- 每个输入生成人声音轨、背景音乐音轨和“保留人声、去背景音乐”视频。
- 去背景音乐视频使用原视频流和分离后的人声轨重新封装，不覆盖原视频。
- 人声或伴奏输出时长与原音频偏差超过验收阈值时，任务失败并保留诊断摘要。

音源分离是最佳努力的 AI 处理，可能有音乐残留、人声失真或分离错误。界面必须说明：去背景音乐只能降低风险，不保证避免 YouTube Content ID、版权申索或其他版权责任。

## 提取字幕

`提取字幕`是与音乐分离独立的任务，并使用相同的逐集/合并范围选择。

处理顺序：

1. ffprobe 检查可提取的文本字幕轨。
2. 存在可转为 SRT 的字幕轨时直接导出，不重新识别。
3. 仅有图像字幕轨、烧录字幕或完全没有字幕轨时，使用 Whisper 根据对白生成 SRT，不引入 OCR。
4. 已有对应人声轨时优先用人声识别；否则从视频导出适合识别的单声道音频。
5. 默认使用 Whisper `small`，输出 UTF-8 SRT，并验证序号、时间轴顺序和时长边界。

音乐分离失败不能阻止字幕识别；无人声轨时回退到原音频。

## 输出目录与命名

在当前剧目下载目录下创建：

- `合并视频/`：合并原音版或 H.264 版。
- `音频分离/`：人声、背景音乐和去背景音乐视频。
- `字幕/`：逐集 SRT 或合并视频 SRT。

文件名使用已清理的剧名和集数，禁止路径穿越和非法字符。同名输出不默认覆盖。

## AI 运行环境与模型管理

设置页新增“媒体处理模型”：

- FFmpeg/ffprobe 内置版本和自检状态。
- AI 运行环境的未安装、下载中、已安装、损坏和可更新状态。
- Demucs 和 Whisper 模型选择、版本、占用空间和存放路径。
- 下载进度、删除、重新下载和完整性检查。

安装规则：

1. 第一次启动 AI 任务时，弹窗列出 AI 运行环境和所选模型的预计下载量与磁盘占用。
2. 组件通过应用发布配置指定的 HTTPS 版本化制品下载，每个制品的版本、平台、大小和 SHA-256 写入随应用发布的非敏感 manifest。
3. 开始前检查可用空间；下载到临时文件，校验成功后原子安装。
4. 校验失败、解压失败或用户取消时不把不完整组件标记为可用。
5. 删除模型不删除已生成的媒体输出；运行中的模型不允许删除。
6. 基础 API sidecar、FFmpeg 和 ffprobe 不经过模型下载器更新，它们跟随应用版本发布。

## YouTube 授权

设置页新增 YouTube 区域，交互顺序为：

1. 导入 Google Desktop OAuth JSON。
2. 校验结构和 Google 授权/令牌端点，拒绝不受支持的凭证类型和非 Google 端点。
3. 将凭证复制到应用私有配置目录，文件权限限制为当前用户可读写。
4. 点击“授权 YouTube”后打开系统默认浏览器，使用 loopback 回调、PKCE S256 和随机 `state`。
5. 只请求 `https://www.googleapis.com/auth/youtube.upload`，不申请字幕管理权限。
6. refresh token 写入 macOS Keychain；access token 只在需要时获取并在内存中使用。

设置页只显示“未配置、已配置、未授权、已授权”和可安全展示的频道信息，不显示 client secret、access token、refresh token 或原始 JSON。“撤销授权”清除钥匙串令牌；“移除凭证”另行删除私有配置副本。

应用不得使用内置 WebView 执行 Google 登录，也不得代替用户选择账号或同意授权。

## YouTube 上传

### 前置条件

`上传 YouTube`仅在以下条件都满足时启用：

- 该剧已有通过验证的合并视频。
- YouTube 凭证已导入并完成用户授权。
- 上传源文件存在且未在确认后发生变更。

应用不会在合并、音乐分离或字幕提取完成后自动上传。每次发布必须由用户点击并完成最终确认。

### 上传弹窗

- 源文件：默认去背景音乐版；可切换为原音频合并版。去背景音乐版尚未生成时回退为原音频合并版并明确提示。
- 标题：默认使用下载记录中的剧名。
- 简介：默认使用下载记录中的剧情简介；缺失时只使用剧名，不编造内容。
- 封面：默认使用下载记录中的剧目封面，允许上传前替换。
- 标签：可从下载类型生成可编辑默认值，例如短剧、真人剧、漫剧或 AI 剧。
- 公开状态：默认 `public`，可修改。
- 观众：默认“不面向儿童”，必须明确确认。
- 合成内容：AI 剧默认勾选，用户可修改，但上传前必须确认。

上传开始时对源文件和封面做快照。封面保持原图内容；必要时转为 JPEG/PNG 并压缩到 YouTube 接口允许的 2 MB 以内。

### 上传协议与结果

- 使用 YouTube resumable upload 创建上传会话。
- 持久化会话 URI、源文件快照和最后已确认范围。
- 网络错误和可重试 5xx 先查询服务端偏移再继续，不假设上一块全部成功或全部失败。
- 401 强制刷新 access token 后重试当前请求，不使用失效缓存令牌。
- 会话返回 404 表示过期时，用户确认后新建会话从头上传。
- 视频上传成功后再使用返回的 video ID 设置自定义封面。
- 封面设置失败不把已上传的视频标记为失败；显示“视频已上传，封面设置失败”并支持单独重试封面。
- 完成时显示 video ID、YouTube 链接和服务端返回的实际隐私状态。

即使用户选择公开，未通过审核的 API 项目也可能被 YouTube 强制为私密。UI 必须展示服务端实际状态，不能根据用户请求值伪报为公开。

## 下载管理与页面交互

下载管理页包含三个分区：

1. **下载任务**：保留现有剧级批次、逐集进度、速度、路径和失败信息。
2. **媒体处理**：合并、转码、音乐分离和字幕任务。
3. **YouTube 上传**：文件、频道、进度、服务端状态和视频链接。

每个已完成的剧级下载批次直接显示四个独立按钮：

- `合并视频`
- `分离背景音乐`
- `提取字幕`
- `上传 YouTube`

任务弹窗关闭后后台任务继续，状态在对应分区可见。每个任务支持进度、取消、失败摘要、重试和打开文件位置。

去重与覆盖规则：

- 同一剧目、范围、输入快照和处理类型已有运行任务时，禁止重复创建。
- 已有完成输出时提示覆盖、另存或取消，默认不覆盖。
- 删除任务记录不删除已生成的文件；删除文件需要不同的明确操作，不在本规格范围内。

## 系统通知

通知类型包含：

- 剧级下载完成或下载失败。
- 新剧监听发现当天上线、且符合用户所选类型的新剧。
- 合并、音乐分离、字幕提取完成。
- YouTube 上传成功或失败。

通知规则：

- 首次需要时请求 macOS 通知权限；用户拒绝后不反复弹窗，设置页提供系统设置引导。
- 应用前台同时显示站内状态，不把系统通知当成唯一结果通道。
- 同一批逐集任务的完成通知合并，不每集弹一次。
- 点击通知打开应用并定位对应剧目或任务。
- 通知只显示剧名、集数和状态，不显示凭证、令牌或敏感错误参数。

## 错误处理

- 内置 FFmpeg/ffprobe 缺失、不可执行或编解码能力不符合时，在设置页和任务入口明确阻断，不尝试未知的系统版本。
- AI 环境或模型未安装时，进入安装确认；下载失败不会让任务假装开始。
- AI Worker 崩溃、超时或输出缺失时终止该任务并保留可重试的脱敏诊断。
- 输入文件缺失或变更时，不继续使用旧任务快照。
- 持久化失败时显示非阻断警告，并明确说明重启后可能无法恢复。
- OAuth 配置错误、用户拒绝、回调超时和令牌失效使用稳定错误代码，不返回原始凭证内容。
- YouTube 上传成功但封面失败是“部分完成”，不可重上传整个视频来重试封面。

## 安全、隐私与版权边界

- 不读取、打印、复制到文档或注入源码的 Google 凭证值。
- 不把 OAuth JSON、refresh token、access token、设备参数、Cookie 或签名头写入日志、快照、通知、安装包或仓库。
- 参数化错误在进入前端前脱敏，子进程命令行不包含 OAuth 令牌。
- 导入凭证和授权只赋予上传所需的最小权限。
- 用户对上传内容、版权、合成内容声明和发布行为负责。AI 分离不构成版权许可或规避工具。

## 测试与验收

### 单元测试

- 媒体任务状态转移、去重键、覆盖选择、取消和重启恢复。
- 输入快照变更检测、路径清理和临时目录隔离。
- ffprobe 结果映射、可无转码合并判定、硬件编码回退和进度解析。
- 字幕轨选择、SRT 格式验证和无人声轨时的回退。
- 模型 manifest 解析、磁盘空间判定、SHA-256 失败和原子安装。
- OAuth 配置结构/端点校验、日志脱敏和钥匙串错误映射。
- YouTube 默认元数据：剧名、简介、封面、类型标签、公开状态、观众和合成内容声明。

### 媒体集成测试

使用本地生成、不包含版权内容的短测试媒体：

- 参数一致的视频可无转码合并，顺序、总时长和可播放性正确。
- 参数不一致时无转码被阻止，H.264 转码输出可播放。
- 取消、中途崩溃和验证失败不破坏原文件，不遗留被标记为完成的半成品。
- 验证人声、背景音乐和去背景音乐视频都能生成和读取；不以测试结果承诺完全分离。
- 覆盖文本字幕轨、无字幕轨、逐集 Whisper 和合并 Whisper，输出 SRT 可解析。

### YouTube 模拟集成测试

- PKCE/state 授权回调成功、拒绝、超时和 `redirect_uri_mismatch` 映射。
- 开始可恢复会话、上传进度、308 查询/续传、401 强制刷新、可重试 5xx 和 404 会话过期。
- 视频上传成功后设置封面，封面失败只生成部分成功状态并可单独重试。
- 端到端脱敏扫描不出现凭证 JSON、client ID 实值、client secret 实值或 OAuth token。

### 前端与原生验收

- 下载管理三个分区、四个独立按钮、范围弹窗、合并转码弹窗和上传确认均可操作。
- 任务排队、进度、取消、失败、重试、中断恢复和打开文件位置状态正确。
- 模型管理展示下载、校验、删除、重下和空间不足状态。
- 通知权限被拒绝时仍有站内结果；逐集完成通知正确合并；点击通知定位相关任务。
- 在目标桌面尺寸和一个窄窗口尺寸检查遮挡、滚动和可点击性。

### 打包验收

- TypeScript/Vite 测试和构建通过。
- Rust fmt、Clippy 和测试通过。
- Python API sidecar 单元和启动测试通过。
- Tauri 安装包内存在可执行的 API sidecar、FFmpeg 和 ffprobe，并附带所需许可说明。
- 从打包后 `.app` 启动，确认普通下载和媒体检查不依赖系统 Python 或系统 FFmpeg。
- 构建 `.dmg`，检查包内无 OAuth JSON、真实凭证值和下载后模型。

### 用户操作的真实验收边界

以下步骤必须由用户亲自完成：

- Google 账号登录、选择频道和同意 OAuth 授权。
- 选择可丢弃的测试视频并确认真实上传。
- 检查 YouTube 服务端的实际隐私状态、封面和处理结果。

实现和交付不得把模拟 YouTube 测试或本地构建误报为真实 OAuth/真实上传已验证。

## 建议实施顺序

本规格保持一个统一用户流程，实施计划应按可独立验收的阶段拆分：

1. 任务模型、持久化、内置 FFmpeg/ffprobe 和自包含 API sidecar。
2. 合并、H.264 转码、输出验证和下载管理任务 UI。
3. AI 运行环境/模型管理、音乐分离和字幕提取。
4. YouTube 凭证、授权、断点上传、元数据继承和封面。
5. 通知收口、全量回归、原生验收和 DMG 交付。

每一阶段必须保持前一阶段的自动化证据，不以后续阶段未完成为由破坏现有下载流程。

## 完成标准

- 用户可在已完成下载批次上独立启动合并、音乐分离、字幕提取和 YouTube 上传。
- 合并顺序、H.264 选择、参数不兼容阻断和文件验证符合本文。
- 音乐分离和字幕提取保持为独立可重试任务，支持逐集/合并范围。
- 任务可持久化，中断、取消和失败不删除原始下载。
- 基础下载应用、FFmpeg 和 API 后端在打包产物中自包含；AI 组件和模型可按需安装和管理。
- YouTube 凭证、授权、上传和封面流程符合最小权限和脱敏规则。
- YouTube 标题、简介和封面默认继承下载记录，用户明确确认后才上传。
- 下载完成、今日新剧、媒体处理和上传结果都有可追踪的站内状态和系统通知。
- 自动化测试、浏览器验收、打包验收和未验证的用户操作边界都有可复核证据。
