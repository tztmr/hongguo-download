# 红果下载：新剧监听、剧场信息、设置与首页分类设计

日期：2026-09-02

## 目标

在现有 macOS Tauri 下载器中完成以下能力：

1. 剧目详情展示上线时间、播放量、热度量、收藏量和点赞量。
2. 新增“新剧监听”页面，按照北京时间当天的上线时间识别新剧。
3. 新增“设置”页面，持久化下载目录、分辨率与通知开关。
4. 首页分类改为真实上游分组，并优化为紧凑的分组横栏。
5. 首页、搜索、榜单和新剧监听统一为桌面端每行 5 部、每组 20 部。
6. 下载批次完成和监听发现新剧时发送 macOS 系统通知。

## 已验证的上游事实

Reqable 合集仅作为接口结构证据，不复制其中的签名、设备标识、Cookie 或令牌到源码或测试。

- 新剧候选接口支持 `selected_items=firstonlinetime_new`，上游原始分页每页 18 条，并不保证结果全部为当天上线。
- 元数据接口 `novel/player/multi_video_detail/preload/v1/` 返回：
  - `create_time`：上线时间 Unix 时间戳。
  - `series_play_cnt`：播放量。
  - `hot_score`：热度量。
  - `followed_cnt`：收藏量。
  - `digg_cnt`：点赞量。
- 分类筛选响应包含“综合、时代背景、主题情节、角色设定”等分组，共 60 多项分类。
- 项目已经具备纯算签名、设备池、设备自动注册、失败换设备和重试能力。新增接口必须复用这些能力，禁止写死抓包签名或设备参数。

## 总体架构

采用“后端统一标准化、前端只消费稳定模型”的方案。

```text
上游候选列表
  -> 现有纯算签名与设备池
  -> 元数据并发补全与短缓存
  -> 北京时间当天过滤、类型过滤、去重和排序
  -> /api/duanju/new-releases（每组最多 20 条）
  -> Tauri invoke
  -> 新剧监听页、导航角标和系统通知
```

前端不直接访问上游，不保存或展示签名头。FastAPI 负责所有上游协议差异和字段映射。

## 后端 API 与数据模型

### 统一剧目信息

扩展标准化剧目模型：

- `book_id` / `series_id`
- `title`
- `cover`
- `content_type`
- `episode_count`
- `abstract`
- `score`
- `category`
- `author`
- `online_time`
- `play_count`
- `hot_count`
- `collect_count`
- `like_count`

统计值为 `0` 时必须保留为零；上游未提供时返回 `null`，前端显示“—”，不能把缺失值伪装为零。

### 今日新剧接口

新增：

```text
GET /api/duanju/new-releases
```

参数：

- `type`：`all`、`playlet`、`comic_series_rank`、`ai_playlet`、`adaptation`。
- `cursor`：后端生成的稳定分页游标，首页为空。
- `limit`：桌面端固定请求 20，后端允许范围 1–20。

返回：

- `items`：标准化剧目，最多 20 条。
- `next_cursor`：下一组游标。
- `has_more`：是否还可继续寻找符合条件的当天新剧。
- `date`：服务端用于筛选的北京时间日期。
- `refreshed_at`：本次刷新完成时间。

处理规则：

1. 根据用户选择的类型使用对应候选列表参数。
2. 读取候选分页，并为候选剧目补充元数据。
3. 把 `create_time` 转为 `Asia/Shanghai`。
4. 仅保留当天 `00:00:00–23:59:59` 上线的剧。
5. 按 `online_time` 从新到旧排序，以 `series_id` 去重。
6. 继续读取上游分页，直到得到 20 条、上游结束或达到安全请求上限。
7. 当天实际不足 20 条时返回实际数量，不能用历史剧目补齐。

候选列表使用短缓存；元数据按剧目 ID 缓存 5 分钟。元数据补全限制并发为 4，避免同时对上游发出 20 个请求。单个剧目元数据失败不应让整组失败：该剧保留基础信息，缺失统计显示“—”，同时返回可诊断但不包含敏感参数的服务端日志。

### 分辨率

下载接口增加 `definition=auto`：

1. 优先选择 1080p。
2. 1080p 不可用时选择 720p。
3. 两者均不可用时沿用当前安全降档逻辑，并在响应头返回实际清晰度。

固定 1080p 和 720p 仍使用现有接口的优先档位与回退规则；下载记录始终保存 API 实际返回的清晰度。

## 首页分类与内容分页

### 分类结构

首页采用已确认的“分组横栏”布局：

- 第一行：内容类型。
- 第二行：分类分组——综合、时代背景、主题情节、角色设定。
- 第三行：当前分组的分类按钮。
- 长分类默认收起，使用“展开/收起”控制，不挤压海报区域。

分类 ID 与分组名称直接来自标准化的上游 selector；切换分类时清空旧分页状态、旧选择和旧详情请求，避免竞态污染新结果。

### 五列与 20 条一组

首页、搜索、榜单、新剧监听统一规则：

- 桌面端内容区每行 5 部。
- 首组严格显示最多 20 部，共 4 行。
- 下拉到接近底部时加载下一组 20 部。
- 上游单页不足 20 条时连续读取分页、按剧目 ID 去重，直到得到 20 条、没有更多内容或达到安全请求上限。
- 榜单编号跨组连续，例如第二组从 `NO.21` 开始。
- 搜索的“匹配识别”在精确标题过滤后继续读取上游分页，直到得到最多 20 个精确结果或没有更多结果。
- 新剧监听当天不足 20 部时只显示实际数量。

加载期间使用单次请求锁和请求序号，防止重复触底调用与旧请求覆盖新筛选结果。

## 新剧监听页面

导航新增“新剧监听”。页面采用已确认的五列数据卡片：

- 海报、标题、类型和集数。
- `HH:mm` 上线时间及“今日新剧”标记。
- 播放量、热度量、收藏量和点赞量。
- 类型筛选：全部、真人剧、漫剧、AI 剧、改编剧。
- 最近刷新时间、“立即刷新”按钮和加载/错误状态。

监听规则：

- 应用打开时每 5 分钟刷新一次；应用关闭后不在后台运行。
- 首次成功加载建立当天基线，不对当前已有剧目集中发送系统通知。
- 后续刷新发现新的 `series_id` 时增加导航角标，并按一次刷新合并成一条系统通知。
- 打开新剧监听页后清除“未查看新增”角标。
- 去重状态按北京时间日期和类型持久化；跨天自动建立新基线并清理过期的当天状态。

## 设置页面与持久化

导航新增“设置”，包含：

- 下载目录：只读路径展示、“选择目录”和“打开目录”。
- 分辨率：自动最高、1080p、720p。
- “下载完成通知”开关，默认开启。
- “新剧通知”开关，默认开启。
- macOS 通知权限状态；权限未授权时显示系统设置提示。

设置保存在 Tauri 应用配置目录的版本化 JSON 中，不依赖浏览器 localStorage：

```json
{
  "version": 1,
  "saveDir": "...",
  "definition": "auto",
  "notifyDownloadComplete": true,
  "notifyNewReleases": true
}
```

写入使用临时文件加原子替换，避免应用异常退出导致半写文件。读取失败时使用默认值并在设置页显示非阻断警告。

修改下载目录后，正在运行的任务继续写入原目标，新启动的任务使用新目录。分辨率在加入队列时写入下载项，已有排队项保持原选择。

## 系统通知

使用 Tauri/macOS 系统通知能力，并提供应用内状态作为通知权限不足时的回退。

### 下载完成

- 单集完成不逐条通知。
- 一个批次由“未全部完成”首次变为“全部完成”时发送一次通知。
- 通知内容包含剧名与完成集数。
- 以批次 ID 记录已通知状态，应用重启后不会对旧批次重复通知。

### 今日新剧

- 同一次刷新发现多部剧时合并成一条通知。
- 通知内容包含新增数量和最多三个剧名，其余使用“等 N 部”概括。
- 同一日期、类型和剧目 ID 只通知一次。
- 无通知权限或开关关闭时仍更新监听页和导航角标。

## 前端组件边界

避免继续扩大 `App.tsx`，新增清晰组件与 hooks：

- `SettingsPage`：设置展示和更新。
- `NewReleasesPage`：监听筛选、五列卡片和刷新状态。
- `CategoryFilter`：分组横栏与展开状态。
- `useAppSettings`：加载、更新和持久化设置。
- `useNewReleaseMonitor`：5 分钟刷新、去重、角标和通知协调。
- 现有下载管理 hook 只负责队列状态；批次完成事件通过稳定回调交给通知协调层。

所有长列表使用稳定的剧目 ID 作为 key，滚动监听保持被动、去重并具备请求锁。

## 错误处理

- 服务离线：页面保留最后一次成功结果，显示离线状态和重试按钮。
- 某部元数据失败：保留剧目卡片，缺失统计显示“—”。
- 日期或时间戳异常：该剧不进入“今日新剧”，服务端记录脱敏诊断。
- 设置写入失败：恢复原设置并显示错误，不假装保存成功。
- 通知权限拒绝：不重复请求权限；设置页提供状态说明。
- 下载 API 实际清晰度降档：下载记录显示实际值，并在完成信息中保留。

## 安全边界

- 不把 Reqable 合集复制进仓库。
- 不记录或显示设备 ID、签名头、Cookie、令牌和完整上游查询串。
- 测试使用手工脱敏的小型 fixture，只保留字段结构。
- 新上游请求全部经过现有签名客户端和设备调度器。
