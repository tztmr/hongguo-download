# v0.3.4

- YouTube 上传列表支持对当前可见的选中任务批量开始、批量暂停，跳过不适用状态，分别报告失败项。
- 单条和批量上传默认使用匹配的去背景音乐视频；没有分离产物时使用合并视频。确认窗口与上传列表显示实际文件完整路径，仍可手动切换。
- 媒体任务删除会显示产物路径，停止活动任务后清理对应模块文件和空目录。合并任务清理合并视频；分离任务清理人声、背景音乐和去背景音乐视频；字幕任务清理字幕。保留原始下载、其他模块文件和无关文件。删除失败保留任务，支持重试；占用中的媒体/视频上传依赖会阻止删除。YouTube 上传列表删除仍只移除上传记录。
- Windows AI 自动调度支持 GPU 任务与 CPU 任务同时运行，按内存、显存、线程预算限制并发。NVENC 合并遇到硬件解码失败时可改用 CPU 解码；无损合并优先保留原始视频帧。
- 本地现代 CUDA 运行时更新包含 GPU 探测、分离显存不足缩小分段、自动 CPU 回退和字幕音频复用。更新仅用于基础工作程序 SHA-256 完全匹配的运行时，并以新文件名并存，不覆盖旧程序或模型。

## 本地 Windows 构建

标准 Windows 构建仍使用 `scripts/build-release-windows.ps1`。可选参数 `-AIBaseWorker <现有现代运行时 exe>` 与 `-AIPython <Python 3.11>` 会通过 PyInstaller 的归档格式重建项目模块，并加上 `tauri.ai-worker.conf.json` 的本地更新资源。依赖模块与原启动器保持一致；发布前应运行新工作程序自检与真实 CUDA 分离/字幕任务。基础工作程序不同的运行时继续使用原程序，可重新构建完整 AI 组件更新。

本次本机构建使用工作区内的 Rust GNU / LLVM 工具链、NSIS，未改动系统构建工具。LLVM 资源编译器适配去除了生成 RC 中的 Windows 长路径前缀。GNU 库测试可执行文件需补入与正式程序相同的 Common Controls v6 manifest；正式应用已包含此 manifest。

验证：前端 326 项通过；Windows Rust 174 项通过、3 项忽略；AI Python 42 项通过（含 CUDA）；本地更新后的冻结工作程序自检、真实 CUDA 分离与字幕提取通过。Windows 兼容的 API/构建检查运行 107 项，105 项通过、2 项跳过；28 项依赖 Unix shell/工具链的发布测试未在本机完成。浏览器预览检查了删除路径窗口、上传列表及最小窗口宽度，未发现横向溢出。正式 Windows 程序通过 DLL 加载检查，检查在应用初始化前停止；未覆盖安装现有应用，未向 YouTube 实际上传视频。
