# v0.3.9 自动追剧流水线调度

## 行为

“同时处理剧目数”改为“每阶段同时处理数”。设置为 1 时，下载、合并、分离背景音乐、字幕、文案封面、上传和清理分别推进。例如 A 剧上传时，B 剧可做 AI 处理、C 剧可合并、D 剧可下载。单部剧仍严格按原来的阶段顺序执行，源文件、输出校验、查重和上传后清理规则保留。

自动追剧不再用全局 `busy.len()` 限制所有推进操作，也不会因最前面的剧目正在等待媒体结果而反复阻塞后面的下载。每个阶段按原队列顺序补位，正在执行的同阶段任务计入上限；暂停、停止、重试等待和频道选择都继续生效。

## 资源与积压

- Windows 媒体调度不再要求合并独占。合并通道最多运行一个任务，与 AI 通道分别计数；AI 并发数为 1 时仍允许一项合并并行。
- 在 CPU、内存、显存允许时，选择最早可运行的媒体任务。前面的 AI 任务等显存或 AI 名额时，后面的合并可以使用空闲资源。非 Windows 平台的媒体并行策略保留，网络和阶段流水线适用于全部平台。
- 合并根据实际 GPU 利用率与可用显存选择是否使用 CPU 空闲资源；无损合并仍然无损，不为占用 GPU 而强制转码。Windows 的 NVENC 故障回退保留。
- 解码、滤镜和编码接收每项合并的 CPU 线程预算；Windows Job Object CPU 总配额同时覆盖合并与 AI，避免新并行任务失去原有的 CPU 限制。
- 新任务启动后预留内存/显存，同一轮调度不会把同一份空闲资源反复分配。未知或不足的资源采取保守等待，暂停的媒体任务仍占用其名额和内存。
- 每个阶段名额最多预备 6 部未完成剧目；设置为 1 时，积压达到 6 部就暂缓新的整部下载。已有部分下载继续收尾，已有积压继续处理，磁盘剩余空间检查保留。

- 回归测试覆盖：上传占用后台操作时仍能下载/合并/分离；积压限流与部分下载恢复；CPU 分离与 GPU 合并共存；第二个合并等待；GPU 忙时 CPU 回退；内存或 CPU 紧张时等待；阻塞的 AI 队列项不挡住后面的合并；单任务暂停、取消、输出持久化与队列继续推进。
