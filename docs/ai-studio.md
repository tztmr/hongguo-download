# AI 创作台：手动真实调用

入口：自动追剧 → AI 文案与封面。自动追剧调度仍未接通；本页的生成按钮会实际调用服务商并使用额度，不自动上传 YouTube。

## 配置与使用

1. 文字服务选择 DeepSeek，模型选择 V4 Pro（`deepseek-v4-pro`）或 V4 Flash（`deepseek-v4-flash`）。分别填写文字服务与封面服务的 API Key。
2. 封面服务选择 Moyuu 或 Jucodex。可查询当前 Key 的模型列表，也可手动输入模型。模型列表可能包含非图片模型，列表查询成功不保证生图成功。
3. 填写原标题和剧情/字幕，选择源封面，点击“生成真实文案”。文字模型使用文字素材，源图在图片生成阶段传入。
4. 选择返回的封面方案，检查提示词和尺寸。“参考源封面”使用 `images/edits` 并实际附加图片；“纯文字生图”使用 `images/generations`。每次只生成一张；失败不自动切换模式或重试。
5. 文案可编辑后应用到上传设置草稿。分类仍需核对；封面以原尺寸显示并可打开。当前没有自动裁切为 16:9、自动保存封面或自动套用封面到 YouTube 的功能。

两个 Key 仅保留在当前页面内存中，刷新或离开页面会清空；切换对应服务商会清除对应 Key。普通设置草稿不保存 Key、视频内容或源图。请求出错不会输出 Key 或上游原始错误体。

## 本地浏览器运行

在仓库根目录的两个终端运行：

```sh
npm --prefix desktop run dev:ai
```

```sh
npm --prefix desktop run dev -- --host 127.0.0.1 --port 1420
```

打开 `http://127.0.0.1:1420/?preview=automation`。前端通过 Vite 的 `/api/studio` 代理访问本机 1426 端口。Python 环境需要仓库 `requirements.txt` 中的依赖。

桌面版本通过 `ai_studio_request` Tauri 命令调用随应用启动的 Python sidecar，复用同一个 `endpoints/ai_studio.py` 实现。分发安装包时必须重新构建包含新增路由的 sidecar 和桌面包；既有安装包不会因修改源码而更新。

## 接口与验证记录（2026-09-13）

- DeepSeek 官方模型列表使用 `deepseek-v4-flash`；旧 `deepseek-flash` 设置与请求已迁移到该名称。已使用用户提供的测试 Key 实测 `deepseek-v4-flash`：返回成功，包含 5 个标题、描述、标签和封面方案。结果仍需核对剧情准确性；V4 Pro 本次未实测。
- Moyuu `/v1/models` 使用用户提供的测试 Key 返回 200、52 个模型。
- `gemini-3.1-flash-image` 在 `/v1/images/generations`、`1024x576` 的一次测试中返回 HTTP 500。不能据此判断该模型的所有接口均不可用。
- `gpt-image-2` 的 `/v1/images/generations` 与 `/v1/images/edits` 各成功一次。后者使用前一次生成的虚构图片作为参考图。两次请求尺寸均为 `1536x1024`，实际返回 PNG 为 `2304x1536`（3:2）；并未证明任意 16:9 尺寸均受支持。
- Jucodex 文档当前环境访问受限。适配器按 OpenAI 兼容路由实现，基地址限定其 HTTPS 域名；需要用户提供确认过的基地址、模型和对应 Key，尚无真实成功记录。
- 本地后端测试覆盖 Key 路由、错误脱敏、来源检查、目的地址校验、文字 JSON 校验、参考图 multipart 和返回图片校验。前端测试覆盖两个 Key、旧结果失效、切换服务清 Key、失败不替换成演示结果。

## 固定图片提示词

图片请求统一使用 `desktop/src/monitor/coverPrompt.ts` 的固定模板，自动填入当前作品名、剧情、语言和可选补充要求。模板包含横版重新构图、主角 50%～65%、按剧情选择 2～4 位配角、HOT 红底黄字、1080 黑金徽章、作品名与 8～12 字钩子、无集数等约束。源素材与补充要求作为 JSON 数据传入，不能覆盖固定规则。

不必先调用文字 AI：填入剧名、剧情和参考海报即可直接生成。文字 AI 返回的封面方案仅作为可选建议；完整图片提示词可在页面展开只读查看。所有此创作台图片请求统一按 `1536x864`（16:9）提交，包括旧草稿保存的方图尺寸；服务商可能返回更高尺寸，界面继续显示实际尺寸。纯文字模式仍需用户主动选择，提示词明确说明没有参考图。

验证：前端 5 项测试包含参考图真实请求参数的模拟断言、无需文字生成、旧尺寸覆盖与当前素材插值；构建通过。Playwright 检查了本地页面自动填入素材及只读模板。本次固定模板改动没有额外调用付费生图接口。


## Key 不可用时的非 AI 回退

缺少文字／封面 Key 时不请求 AI；上游 401 或 403 返回结构化 `AI_KEY_INVALID`，网页与 Tauri 均保留此错误码并跳过 AI。清除本次 AI 结果，恢复应用 AI 文案前保存的非 AI 标题、简介和标签模板，不改频道、可见性、视频分类、字幕或查重设置。普通网络错误、限流、查重错误不误判成失效 Key。

现有「下载管理 → YouTube 上传」始终可直接使用剧名、源简介、分类标签和原封面处理路径，不需要任何 AI Key。自动追剧仍是设置预览，没有启用后台自动上传；AI 回退不在试跑页面擅自发起上传。

## v0.3.5 固定文字提示词

所有文字生成请求自动包含 `textPrompt.ts` 的固定运营编辑规则，旧草稿无需重置：3 个 A/B/C 标题（情绪冲突、剧情反转、强点击），明确推荐；标题约 35～60 个中文字，不写集数、可保留作品已有季数；简介正文 300～500 字，保留悬念而不编造或剧透结局；8～12 个相关 Hashtag。结果支持按指定格式复制完整方案，应用草稿时将 Hashtag 放入描述末尾并保留视频标签字段。原有封面固定规则保持生效。
