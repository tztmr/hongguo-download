# 首页推荐与 Windows 媒体并行改进

## 行为

- 首页“全部”接入现有真人剧发现、漫剧发现和 AI 剧推荐榜，交错展示并去重。各来源独立保存分页状态；失败来源单独提示、单独重试，保留正常内容。
- 漫剧分类优先采用发现接口返回的分类 ID，避免重复读取和使用另一套分类字典。AI 题材只筛选已加载结果，切换题材同步右侧详情。异常空响应仍可重试，正常空末页和不推进的分页状态停止翻页。
- Windows 的 AI 设备选择“自动”时，首个 GPU 任务启动后，在 CPU、内存及名额允许的情况下分配 CPU 任务，避免 GPU 利用率尚未更新时把全部名额都占满。GPU 繁忙或显存不足时继续利用 CPU；明确指定 CUDA 的任务保持 CUDA。AI 同时处理数设为 1 时仍按顺序执行。
- Windows 智能合并允许一个 GPU 通道和一个 CPU 通道并行处理不同剧目；CPU/内存不足时等待。同一剧目的正片和 Shorts 合并保持顺序，避免输出冲突。兼容的视频仍无损复制，仅必要时转码；运行中任务不迁移设备。
- CPU 采样计时与资源缓存计时分开，频繁唤醒不会阻止首次有效 CPU 采样。每个工作进程继续遵守线程预算。自动追剧页面可保存设备偏好，分离进度显示实际设备；仅装 CPU 运行环境也能通过自动模式组件检查。

## 验证

- 前端完整测试：54 个文件、440 项通过；TypeScript 和生产构建通过。
- Rust 完整库测试：431 项通过、6 项需显式运行环境的测试忽略；Clippy（lib、tests，禁止警告）通过。
- 新增真实媒体队列回归：阻塞首个 GPU 任务直到取消，同时观察 CPU 任务启动；验证两个合并通道、同目录串行、通道完成后补位及 AI 总并发限制。
- 在 macOS 使用本地 FFmpeg 8.0.1 跑 Windows 合并实现：CPU 转码、混合参数、不同时间基、音轨补齐、方形 Shorts、时长及帧数验证通过。这不等于 Windows 驱动或 NVENC 实机测试。
- Python 接口/工作进程回归：94 项中 84 项通过，10 项因缺少 Demucs 依赖、模型或 CUDA 环境跳过。
- 浏览器交互使用受控 API 返回：16 条正常推荐保留，重试只重新请求失败的漫剧来源；漫剧分类携带接口 ID，AI 题材过滤同步详情。自动追剧设备保存与全局设置同步有组件交互回归覆盖。
- Windows/macOS CI 均加入首页接口分页回归。工作流结果和安装包发布需单独核实；本次源码验证没有替换用户已安装的 0.5.1。

## 边界

并行利用 CPU 和 GPU 的单位是不同任务，需要有多个待处理任务。不会为提高硬件占用率强制转码，也不会保证 CPU、GPU 同时达到 100%。本次未执行真实上游推荐接口采集、Windows 显卡负载实测或完整自动追剧上传。
