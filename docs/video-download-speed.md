# v0.3.1 视频下载优化

视频下载复用已有 CDN 连接池。此前备用地址只检查首包等待：一旦收到首包，后续卡住或持续低速时只能等该请求完成／超时，拖住下载队列。

现在整个传输期间监测进度：首包等待 2 秒、已有数据后停顿 3 秒，或传输超过 8 秒且平均速度不足 256 KiB/s 时，尝试备用地址。每集最多同时使用两条线路；只有完整、通过现有校验的响应才成为结果，其余请求及时关闭。正常速度下载不会额外拉取备用副本。保留原有并发设置、清晰度和解密流程。

验证包含首包停顿、中途停顿、持续低速、正常持续传输、备用数据无效、两条线路上限以及取消时释放连接。`scripts/verify-download-failover.py` 使用真实本地 HTTP 连接和合成内容，模拟主线路首包后暂停 6 秒：旧逻辑约 6 秒完成，新逻辑约 3 秒取得完整备用内容。该结果验证慢线路恢复耗时，不代表所有实际 CDN 或用户网络都能达到固定倍数提速。

可重现：

```sh
python3 -m unittest tests.test_video_download -v
python3 scripts/verify-download-failover.py
# 可用 --baseline /path/to/old_video_download.py 对比旧实现。
```

此优化位于内置 API。macOS 安装包需重新打包 API 辅助程序，并通过源码指纹检查；仅替换网页资源不会生效。
