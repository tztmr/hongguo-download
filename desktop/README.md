# 红果下载

基于现有番茄短剧纯算 API 的 macOS 桌面下载器。应用启动后会在本机拉起 FastAPI，走 `/api/duanju/download` 完成 CENC 解密，并把可播放 MP4 写到本机目录。

## 功能

- 发现页：真人剧 / 漫剧推荐流，支持翻页
- 排行榜：真人剧 / 漫剧 / AI剧分别查看推荐、热播、臻果、预约、新剧、热搜、必看、收藏 8 个榜单，持续翻页到上游结束
- 今日新剧：真人剧 / 漫剧 / AI剧三类监听，并按校园、古风等标签细分；当天结果本地累计保存
- 搜索：关键词搜索后选剧、选集成片
- 下载队列：串行下载，进度条，完成后可在 Finder 中显示
- 默认保存到 `~/Downloads/红果下载/<剧名>/`
- 下载完成后可合并视频，并按集或按合并视频分离背景音乐、提取 SRT 字幕
- 使用 Google 桌面 OAuth 在系统浏览器授权 YouTube，支持可恢复上传、取消/重试和封面部分失败重试
- 下载、新剧、媒体任务和 YouTube 上传均可独立控制系统通知

## 界面与搜索（0.1.10）

下载管理与 YouTube 上传支持按任务状态和剧名筛选；通知定位会清除筛选。上传页显示并发处理、排队、暂停与需要处理的任务统计，并突出暂停、继续和封面重试操作。设置页增加当前配置概览与分类导航，适配较小窗口。

首页和搜索默认选择“全部”，首页交错展示真人剧与漫剧，分别保留分页游标；榜单也默认选择全部。搜索提交后立即进入结果页，离开再返回可恢复结果。缓存按关键词、内容类型和匹配方式隔离，保留 5 分钟，最多 20 组、每组 500 项；相同请求进行中时复用请求，失败不缓存，支持手动刷新。加载更多只使用已提交的关键词。

## 智能合并（0.1.6）

合并默认使用“智能合并”：各集画面参数、编码配置和时间轴兼容时直接复制视频，保留原始画质；音轨逐集解码、校正，再编码一次 AAC，避免 AAC 编码延迟和补齐样本在多集拼接中累积。画面不兼容时逐集统一为第一集的尺寸和帧率，保持画面比例，再合并。也可选择“仅无损合并”或“统一转为 H.264”。

“画质优先 / 均衡 / 小体积”仅作用于转码。优先使用 Apple VideoToolbox 硬件编码；硬件编码器不可用时整项任务统一回退到软件编码。中间音轨使用 PCM，最终只编码一次 AAC，避免每集重复 AAC 编码造成接缝误差。逐集转码需要额外临时磁盘空间，任务结束或取消后清理。

输出总时长误差上限为 0.25 秒；新任务还流式扫描全片音视频包，检查起止偏差、时间轴缺口和重叠，还检查实际解码音频样本总时长，阈值为 0.12 秒。智能模式无损成片校验失败时会尝试转码，仍不合格则阻止发布。此检查能发现媒体时间轴异常，不能判断源视频的人物口型与语音内容是否一致。

暂停、继续和取消同样适用于新流程的检测、转码和校验子进程。升级前保存的任务继续保留原合并方式，新建任务才默认使用智能合并。

## 开发

```bash
cd desktop
npm install
npx tauri dev
```

需要本机 Python 3，以及仓库根目录已安装 `requirements.txt` 依赖。

## 打包

```bash
./scripts/build-api-sidecar.sh
cd desktop
npx tauri build --config '{"bundle":{"externalBin":["binaries/hongguo-api"]}}'
```

上面的包包含本地 API，可运行榜单、新剧监听和常规下载。若要同时打包媒体处理功能，先按 `scripts/stage-media-tools.sh` 的要求提供并校验 FFmpeg/ffprobe 归档，再用 `src-tauri/tauri.release.conf.json` 构建完整 release 包。

完整发布必须使用仓库根目录的 `scripts/build-release.sh`。它会在任何构建写入前检查 FFmpeg/ffprobe 归档、SHA-256，以及五个 AI 组件的 HTTPS 发布地址、版本和校验值；缺一项就退出。成功构建后会自动调用 `scripts/verify-release.sh` 检查 ARM64 架构、可执行权限、最小 PATH 健康探针、许可证、凭证/模型泄漏、签名和 DMG。

AI 下载地址在构建预检、清单生成和安装包验证时共用 `scripts/release_urls.py`：拒绝 `.invalid`、`.test`、示例域名、本机/私有 IP、缺失主机、非法端口和带账号密码的地址。校验在清单写入或构建启动前执行，不会用无效地址覆盖原有清单。这是离线配置检查；真实链接能否下载、下载内容是否匹配 SHA-256，仍需在上传后验证。

2026-09-05 核对的五个本地 AI 压缩包及其 SHA-256、下载体积、解压文件体积已记录在 `dist/release-upload-inventory.json`，对应环境变量已整理到 `dist/release.env`。先把清单中的五个文件按原名上传到同一个真实 HTTPS 目录，再在仓库根目录设置 `HONGGUO_AI_BASE_URL`、执行 `source dist/release.env` 和 `./scripts/build-release.sh`。未设置下载目录时配置会报错退出。已有 0.1.0 安装包仍含占位地址，需在真实地址确定后重建。

## AI 组件

基础安装包不包含 PyTorch、Demucs、Whisper 或模型权重。第一次点击“分离背景音乐”或“提取字幕”时，应用会列出下载体积与安装后占用并要求确认。组件从清单中的 HTTPS 地址下载，经过 SHA-256、自检和原子发布后存放在应用数据目录；可在设置中删除或重新下载。

整季音频按约 2 分钟一段分离，段间保留上下文并交叉淡化，模型只加载一次，结果逐段写入磁盘，避免内存随整季时长增长。处理时实时显示段数和进度；MPS 算子不支持或显存不足时，自动用 CPU 重试当前段并继续后续处理。CPU 模式耗时会更长。更新此功能需要同时重新构建桌面端和 AI runtime，并更新 runtime 版本、归档校验值及体积；仅更新桌面应用不会替换已经安装的旧 AI 工作程序。

发布的模型归档必须直接展开到组件根目录。`demucs-htdemucs` 必须包含 `htdemucs.yaml` 及其 `models` 列表引用的全部 `<signature>[-checksum].th`；`demucs-htdemucs_ft` 对应 `htdemucs_ft.yaml` 及四个权重；Whisper 归档分别必须包含 `small.pt` 或 `medium.pt`。任何缺失、空文件或符号链接都会在任务启动前失败，Whisper 不会用运行时联网下载来补齐不完整的发布包。

权重文件准备好后，用下面的命令生成四个可安装归档和 `release-metadata.json`；该脚本会检查 Demucs bag 引用的权重是否齐全，并把 Whisper 文件规范化为运行时要求的名称。归档上传到自有 HTTPS 发布地址后，再将元数据中的 SHA-256 和体积写入发布环境变量。

```bash
python3 scripts/build-ai-model-archives.py \
  --demucs-dir /path/to/demucs-repo \
  --whisper-small /path/to/small.pt \
  --whisper-medium /path/to/medium.pt \
  --output-dir dist/ai-model-components
```

音频分离可能残留、失真或影响对白，不能保证规避 YouTube Content ID，也不改变素材版权或平台责任。字幕识别结果需要人工校对。

## YouTube 授权与上传

确认上传时会读取所选频道的全部上传列表，按去掉首尾空格、忽略大小写后的标题查重；频道影片标题包含剧名（忽略空格、标点）时提示可能重复。发现匹配会显示已有视频链接，默认选择“跳过本次上传”，也可点击“仍然上传”。查询失败时保留弹窗并允许重试，不会当作没有重复继续上传。

本应用从现在起记录频道、剧集 ID 和视频 ID，改标题或删除本地上传任务后仍可提醒同剧重复；历史上手动上传的视频主要按标题识别。记录保存在应用数据目录的 `youtube/upload-history.json`。本地历史提醒不代表该视频目前仍在频道中，可核对链接后决定是否继续。新建任务入队前会再次核对频道和重复项，同时拦截队列内的同剧任务；恢复原上传会话无需重建上传。

0.1.9 将并发上限调整为 5 个，并提供暂停、继续。暂停会保留上传会话、释放上传名额，重启后保持暂停；继续和失败重试先核对服务器偏移再续传，并重新创建读取系统代理的 HTTP 客户端。断线、临时服务错误采用有限次数的退避重试，最后完成响应丢失时查询已有上传结果。会话过期则提示重新创建上传任务，不自动重复发布。创建上传会话时点击暂停，会先保存返回的会话地址（请求最多等待 30 秒）。

0.1.9 同时修复封面转换：优先使用 macOS 原生图片工具，解决内置 FFmpeg 缺少 PNG 解码器导致的失败；按比例缩放、逐步压缩到 1.9 MB 内，保留原图。无法解码时报告转换失败，不再误报超出大小。视频已上传、封面失败的任务可仅重试封面。

使用 v2rayN 的系统代理模式时，应保持 macOS 系统代理配置有效；切换节点后可暂停再继续，失败时点重试。应用不会自动更改系统代理。协议参考：[YouTube resumable uploads](https://developers.google.com/youtube/v3/guides/using_resumable_upload_protocol)。

0.1.8 支持最多同时上传 3 个视频，其余自动排队；上传完成、失败或取消后自动补位，重启恢复全部未完成任务。排队任务可以直接取消，重试也遵守并发上限。同一频道同一文件不会重复加入正在运行的队列；各任务的封面临时文件独立保存。上传列表显示正在处理与排队数量。

0.1.7 修复删除合并任务记录后，整季去背景音乐视频无法打开上传窗口的问题。上传文件优先选择同一剧集、同一下载目录中已完成的整季去背景音乐 MP4；逐集分离结果不会误选为整季视频。窗口显示实际上传路径，缺少凭证或频道时按钮分别提示原因。

先在 Google Cloud 创建“桌面应用”OAuth 客户端并启用 YouTube Data API v3，然后在设置中选择下载的 JSON。应用只把通过校验的凭证私密复制到应用配置目录；刷新令牌存入 macOS 钥匙串，不写入普通状态文件或日志。授权请求 `youtube.upload` 和 `youtube.readonly`，分别用于上传及读取当前账号的频道信息；登录和同意必须由用户在系统浏览器中亲自完成。Google 请求使用系统代理，收到有效回调后应用会尝试恢复窗口并切到前台。

上传只接受本应用验证完成的合并视频，默认优先使用合并范围生成的去背景音乐视频。发布前必须分别确认儿童受众、合成内容披露和最终发布。Google 可能把未完成审核的 OAuth 项目上传内容强制设为私享，界面以服务器返回的实际状态为准。撤销频道授权或删除本机 OAuth 配置可在设置中完成。

自动化测试不等于真实账号验收。真实 Google 同意和一次可删除测试视频的上传，需要用户在发布包中亲自执行。

### Whisper 转写运行环境

0.1.6 的转写任务在桌面端固定选择 CPU，并为已有 runtime 明确设置打包 FFmpeg 的搜索路径，修复 Torch 2.5.1 的 SparseMPS 不支持错误以及 Finder 启动时找不到 ffmpeg 的错误。背景音乐分离继续使用原有设备选择。无需重新下载 runtime 或模型。

### 0.1.15 升级与发布

AI 请求使用 ASCII JSON 转义保留中文、空格和 emoji 路径；读取结果兼容 UTF-8 和旧 Windows runtime 的 GBK，无需删除或重新下载模型。背景音乐分离与转写均优先使用应用内 FFmpeg，Windows 的 PATH 使用可搜索的目录格式。工作程序失败时保留有界 stderr 诊断，并在异常退出提示中显示退出状态。

Windows 安装器按 Tauri 的实际主程序名结束运行中的进程树，再替换文件。打包 CI 在中文空格安装目录验证：从上一版运行中升级、同版本运行中重装、设置目录保留、安装文件哈希和升级后启动。手动执行这些安装测试会安装及卸载应用，只应在隔离测试机器上使用 `verify-release-windows.ps1 -InstallSmokeTest`。

macOS 退出应用后，将 DMG 中的“红果下载”拖入 Applications 并选择替换；应用名称与数据目录标识保持稳定，已有设置和 AI 组件继续保留。

开发及 CI 统一使用 main。Windows 通过 `windows-release.yml` 构建，传入 FFmpeg 下载地址、SHA-256 和用于升级测试的上一版本 tag。macOS 在本机加载 `dist/release.env` 后执行 `./scripts/build-release.sh`，完成检查后，将生成的当前版本 DMG 用 `gh release upload <tag> <dmg-path>` 上传到同一发布版本，无需等待云端 macOS 打包。


### 0.1.16 AI 结果隔离与中断恢复

分离和字幕结果按“整季/逐集”分别存放，每个完整结果目录都有来源记录。记录包含源视频规范路径、大小、修改时间、集号、模型、运行环境目录和计算设备；新增其他集数不会使已有单集结果失效。字幕只复用来源快照和处理范围一致的人声音轨。源视频在运行前或保存前发生变化时，任务会拒绝复用或发布结果。

新目录形式为 `音频分离/整季/001_htdemucs_<身份标识>-<结果标识>/`（逐集使用 `逐集`），其中包含 `人声.wav`、`背景音乐.wav`、`去背景音乐.mp4` 和 `result.json`；字幕使用相同目录规则，文件为 `字幕.srt`。缓存复用需匹配完整来源记录及输出文件大小、修改时间，不对大型视频反复读取全文件计算内容哈希。

所有文件校验完成后，先在同一文件系统的临时目录准备完整结果，再整体重命名到最终目录。保存中断不会暴露半份可复用结果；若最终目录已发布但任务记录未保存，重试可直接恢复完整结果。损坏或缺失文件会触发重新生成新的结果目录，旧文件与历史任务路径保留。临时目录使用随机标识，避免异常退出后的残留目录阻塞下次运行。

旧版平铺结果没有可靠的来源记录，会继续保留，但不自动作为新任务的缓存或字幕人声输入；第一次重新处理会生成可验证的新结果。


## v0.2.0 下载与媒体任务操作

- 提交合并、分离背景音乐或 YouTube 上传后保留当前页面和选中剧目，成功消息显示 3 秒。
- 下载管理返回后保留剧目、筛选和勾选；媒体与上传分区之间切换也保留各自的筛选和勾选。
- 下载列表支持批量删除记录、批量合并、批量上传；媒体列表支持批量删除和批量上传；YouTube 列表支持批量删除本地任务。
- 全选及批量操作针对当前可见列表。每部剧单独合并，已存在的成片和未下载完成的任务会跳过；失败项可单独重试。
- 合并成片旁提供“分离视频”和“上传 YouTube”，整季去背景音乐视频旁提供上传入口。
- 批量上传逐部保留标题、简介和标签，默认私享；逐项查重，重复项默认跳过，失败重试不会重复提交已成功入队的项目。
- 修复延迟进度事件将已完成下载改回下载中的问题，并恢复有完整完成凭据的旧记录。

## v0.2.0 在线观看与评论量

剧集详情面板新增“在线观看”，从已选的第一集开始，无选择时从第一集开始；支持选集、上一集／下一集、播放控制与失败重试。首次播放需要先缓冲整集，关闭或切集时取消前端请求并释放视频缓存。

详情面板将“点赞量”替换为“评论量”，优先读取整剧评论总数；没有总数时，仅在全部剧集数据齐全时汇总各集评论，缺失数据显示 `—`。

播放器共用跨平台实现。macOS WKWebView 与 Windows WebView2 的视频格式支持取决于系统运行环境，安装包中的播放功能需分别验证，浏览器测试不替代两端桌面实测。
